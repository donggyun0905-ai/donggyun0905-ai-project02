> 자세한 필드·파라미터는 [`../api-usage.md`](../api-usage.md), 테이블 정의는 [`../db-design.md`](../db-design.md) 참고.

| API | 쓰는 곳 | 하는 일 | 저장 위치 |
| --- | --- | --- | --- |
| **채용정보** | 격차 분석 | 공고에서 직무별 요구 기술을 뽑는다 | `JOB_REQUIRED_SKILL` |
| | 인사이트 | 월별로 많이 요구되는 기술을 쌓는다 | `JOB_SKILL_TREND` |

| | 로드맵 | "왜 이걸 해야 하는지" 설명 재료로 쓴다 | 저장 안 함 |

| 구직자취업역량 강화프로그램 | – | 쓰지 않음 | – |

모든 호출 결과는 `EXTERNAL_API_CACHE`에 저장해 두고, 고용24가 안 될 때 대신 보여준다.

## 어디에 어떤 데이터를 넣나

### 채용정보 — 주 1회 배치, 한 번에 4개 테이블

| 테이블 | 넣는 데이터 |
| --- | --- |
| `JOB_REQUIRED_SKILL` | 직무 × 기술 한 줄씩. 자격요건에서 나온 기술은 `REQUIRED`, 우대사항에서만 나온 기술은 `PREFERRED`. `source='WORKNET'` |
| `JOB_SKILL_TREND` | 직무 × 기술 × 월. 이번 달 공고 중 언급된 건수와 비율 |
| `JOB` | `last_collected_at`만 갱신 (다음 수집 시점 판단) |
| `EXTERNAL_API_CACHE` | 받아온 원본 응답 그대로 |

사용자가 공고를 D-day로 등록하면 그때 `DDAY_ALERT`에 1건 (공고 제목, 마감일, `RECRUIT`).

### 직무정보 — 공고가 없는 직무만, 한 번에 2개 테이블

| 테이블 | 넣는 데이터 |
| --- | --- |
| `JOB_REQUIRED_SKILL` | NCS 지식·기술·태도에서 찾은 기술. `REQUIRED` |
| `EXTERNAL_API_CACHE` | 받아온 원본 응답 그대로 |

### 학과정보 — 1개 테이블

| 테이블 | 넣는 데이터 |
| --- | --- |
| `USERS` | `major`에 사용자가 고른 표준 학과명 (프로필 저장 시) |
| `EXTERNAL_API_CACHE` | 전체 학과 목록 (자동완성용, 한 번만 받아둠) |

### 저장 순서

1. **캐시 먼저, 따로 저장** — 뒤에서 오류가 나도 원본은 남아야 다음 실패 때 대신 보여줄 수 있다.
2. **나머지는 직무 하나씩 트랜잭션** (`TransactionUtil`) — 한 직무가 실패해도 다른 직무 결과는 남는다.
