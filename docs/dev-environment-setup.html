1공통 준비

IDE와 상관없이 모두 한 번씩 해야 합니다.

설치할 것 처음 한 번

항목버전비고
JDK17 이상설치 후 터미널에서 java -version으로 확인
Tomcat10.1 이상압축만 풀어 두면 됩니다 (예: C:\Tomcat). VS Code는 확장이 대신 받아 줄 수도 있습니다.
Maven설치 불필요프로젝트의 Maven Wrapper(mvnw)가 첫 빌드 때 자동으로 받습니다.

톰캣 포트를 80으로 설정 처음 한 번

우리 프로젝트는 80 포트를 씁니다. IntelliJ·VS Code 모두 같은 톰캣 설정을 따릅니다.

  1. 톰캣 폴더의 conf/server.xml을 열고 HTTP Connector 포트를 80으로 바꿉니다.
    conf/server.xml
    <Connector port="80" protocol="HTTP/1.1"
           connectionTimeout="20000"
           redirectPort="8443" />
  2. Windows의 IIS를 끕니다. IIS가 켜져 있으면 80 포트를 먼저 차지해서 톰캣이 뜨지 못하고 403이 뜹니다. 관리자 권한 PowerShell에서 실행하세요.
    관리자 PowerShell
    Stop-Service W3SVC, WAS -Force
Set-Service W3SVC -StartupType Disabled

    IIS가 설치돼 있지 않은 PC라면 "서비스를 찾을 수 없다"는 오류가 나는데, 그냥 넘어가면 됩니다.

  3. (선택) 같은 파일의 <Server port="-1">을 port="8005"로 바꾸면 톰캣 종료 시 SEVERE 메시지가 사라집니다.
IntelliJ와 VS Code의 톰캣을 동시에 켜지 마세요둘 다 80 포트를 쓰므로 나중에 켠 쪽이 실패합니다. 한쪽을 끄고 다른 쪽을 켜세요.

설정 파일 만들기 처음 한 번

  1. 프로젝트 루트의 config.properties.example을 복사해 같은 위치에 config.properties로 저장합니다.
  2. DB 접속 정보를 채웁니다. 값은 팀 채널에서 받으세요.
    config.properties
    DB_URL=jdbc:mysql://<호스트>:<포트>/spec_odyssey?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Seoul&characterEncoding=UTF-8
DB_USER=<아이디>
DB_PASSWORD=<비밀번호>
config.properties는 절대 커밋하지 마세요.gitignore에 등록돼 있어 git add .로는 올라가지 않습니다. git add -f로 강제로 올리지 마세요.

빌드 확인 처음 한 번

프로젝트 루트에서 실행합니다.

Windows
.\mvnw.cmd package -DskipTests
macOS / Linux
./mvnw package -DskipTests
성공 기준target/spec-odyssey.war 파일과 target/spec-odyssey/ 폴더가 생기면 됩니다.

2IntelliJ IDEA에서 실행

프로젝트 열기 & Maven 인식 처음 한 번

  1. File → Open으로 프로젝트 폴더를 엽니다.
  2. 오른쪽 아래 Maven build scripts found 알림이 뜨면 Load를 누릅니다.
    알림이 없으면 pom.xml 우클릭 → Add as Maven Project (이미 되어 있으면 Maven → Reload project)
  3. 오른쪽 Maven 패널에 spec-odyssey가 보이면 완료입니다.

톰캣 등록 & 실행 설정 처음 한 번

  1. Run → Edit Configurations... → 왼쪽 위 + → Tomcat Server → Local
  2. Server 탭
    • Application server 옆 Configure... → 톰캣 설치 폴더 (예: C:\Tomcat)
    • HTTP port → 80
  3. Deployment 탭
    • + → Artifact... → spec-odyssey:war exploded
    • Application context → /specodyssey
  4. OK → 오른쪽 위 실행(▶) 버튼 → http://localhost/specodyssey/ 접속
Artifact 목록에 spec-odyssey:war exploded가 없다면 Maven 인식이 안 된 상태입니다. 위의 Maven 인식을 다시 하거나, IntelliJ의 Maven 인식과 상관없이 동작하는 아래 방법을 쓰세요.
  1. Deployment 탭 → + → External Source... → target/spec-odyssey 폴더 선택, context는 /specodyssey
  2. 같은 화면 아래 Before launch에서 기존 Build를 지우고 + → Run Maven Goal → package -DskipTests 입력
실행할 때마다 Maven으로 빌드한 뒤 배포됩니다.

코드 수정 후 매번

코드·JSP 수정→실행 창의 재시작(↻)→브라우저 새로고침

config.properties를 고쳤을 때도 재시작하면 반영됩니다.

3VS Code에서 실행

확장 설치 처음 한 번

  • Extension Pack for Java — Microsoft
  • Community Server Connectors — Red Hat

톰캣 서버 만들기 처음 한 번

  1. 먼저 빌드를 한 번 해서 target/spec-odyssey/ 폴더를 만들어 둡니다.
  2. 왼쪽 아래 SERVERS 패널 → Community Server Connector 우클릭 → Create New Server...
  3. Download server? 질문에서
    • 톰캣이 이미 있으면 No, use server on disk → 톰캣 폴더 선택 (bin, conf, lib, webapps가 바로 들어 있는 폴더)
    • 없으면 Yes → 목록에서 Apache Tomcat 10.1.x
  4. 설정 화면은 기본값 그대로 Finish

배포 & 자동 Publish 설정 처음 한 번 권장

war 파일 대신 폴더로 배포하고 자동 Publish를 켜 두면, 이후에는 빌드만 해도 톰캣에 자동으로 반영됩니다.

  1. 만든 서버 우클릭 → Add Deployment → Exploded → target/spec-odyssey 폴더 선택
  2. 서버 우클릭 → Edit Server → 열린 JSON 파일에서 아래 두 가지를 확인·추가하고 저장(Ctrl+S)합니다.
    Edit Server (JSON)
    {
  ...
  "server.http.port": "80",                ← 기본값 8080을 80으로 변경
  "server.autopublish.enabled": "true",  ← 이 줄 추가
  ...
}
  3. 서버 우클릭 → Start Server → 상태가 Started가 되면 http://localhost/spec-odyssey/ 접속
    처음 한 번은 앱이 안 올라가 있을 수 있습니다. 404가 뜨면 서버 우클릭 → Publish Server (Full)을 한 번 누르세요.
포트는 반드시 맞추세요 — 가장 많이 걸리는 지점 server.http.port와 톰캣 conf/server.xml의 <Connector port="...">가 다르면, 확장이 톰캣이 켜진 걸 감지하지 못해 앱을 배포하지 않습니다 (계속 404).

Ctrl+Shift+B로 빌드하기 처음 한 번 권장

프로젝트에 .vscode/tasks.json 파일을 만들고 아래 내용을 붙여 넣으면, Ctrl+Shift+B 한 번으로 빌드됩니다.

.vscode/tasks.json
{
  "version": "2.0.0",
  "tasks": [{
    "label": "build webapp",
    "type": "shell",
    "command": ".\\mvnw.cmd -q compile war:exploded",
    "group": { "kind": "build", "isDefault": true }
  }]
}
참고 compile war:exploded는 war 압축을 만들지 않고 배포 중인 폴더(target/spec-odyssey)만 갱신해서 package보다 빠릅니다. .vscode/는 .gitignore 대상이라 각자 만들어야 합니다.

코드 수정 후 매번

코드·JSP 수정→Ctrl+Shift+B→브라우저 새로고침

반영이 안 되면 그때만 서버 우클릭 → Publish Server (Full)을 누르세요.

자동 Publish·tasks.json을 설정하지 않았다면 매번 .\mvnw.cmd package -DskipTests로 빌드한 뒤 서버 우클릭 → Publish Server (Full)을 눌러야 합니다.

4자주 나는 문제와 해결

제목을 누르면 펼쳐집니다.

localhost 접속 시 "액세스가 거부됨 / HTTP ERROR 403"

원인: 톰캣이 아니라 Windows의 IIS가 응답하는 것입니다. IIS가 80 포트를 먼저 차지해 톰캣이 뜨지 못했습니다.

관리자 권한 PowerShell에서 IIS를 끈 뒤 톰캣을 다시 실행하세요.

관리자 PowerShell
Stop-Service W3SVC, WAS -Force
Set-Service W3SVC -StartupType Disabled

되돌리기: Set-Service W3SVC -StartupType Automatic; Start-Service W3SVC

톰캣은 떴는데 404

원인: 앱이 배포되지 않았습니다. 톰캣의 webapps 폴더에 spec-odyssey가 있는지 보면 알 수 있습니다.

  • IntelliJ: Deployment 탭에 항목이 있는지, Application context가 주소와 같은지 확인
  • VS Code: server.http.port가 실제 톰캣 포트와 같은지 확인 → Publish Server (Full)
VS Code: "Unable to create the server: Extension backend error - connection is disposed"

원인: 확장의 백엔드 프로세스가 죽었는데 잠금 파일이 남아 있습니다. 확장 자동 업데이트 직후 자주 생깁니다.

  1. VS Code 창을 모두 닫습니다.
  2. %USERPROFILE%\.rsp\redhat-community-server-connector\.lock 파일을 삭제합니다.
  3. VS Code를 다시 열고 서버를 다시 만듭니다.

그래도 안 되면 VS Code settings.json에 백엔드용 Java 21을 지정합니다. Java 확장에 포함된 JRE 경로이며 버전 숫자는 PC마다 다릅니다.

settings.json
"rsp-ui.rsp.java.home": "C:\\Users\\<사용자>\\.vscode\\extensions\\redhat.java-<버전>-win32-x64\\jre\\<21.x>-win32-x86_64"
톰캣 종료 시 "셧다운 포트가 설정되지 않았습니다" (SEVERE)

원인: 톰캣 conf/server.xml의 <Server port="-1"> 설정입니다.

강제 종료되므로 동작에는 문제없습니다. 메시지를 없애려면 port="8005"로 바꾸세요.

DB 연결 실패
오류 메시지원인 / 해결
"config.properties(또는 환경변수)에 DB_URL, DB_USER, DB_PASSWORD를 설정해야 합니다" config.properties가 프로젝트 루트에 없거나 키 이름이 다릅니다. 고친 뒤 다시 빌드하세요 (빌드할 때 앱 안으로 복사됩니다).
UnknownHostExceptionDB_URL의 호스트 주소 오타
Communications link failureDB 서버가 꺼져 있거나 포트·방화벽 문제
Access denied for user아이디 또는 비밀번호 오류
컴파일 오류: javax.servlet을 찾을 수 없음

원인: Tomcat 10.1+는 jakarta.servlet.*을 씁니다. 인터넷 예제는 대부분 구버전(javax) 기준입니다.

  • import는 jakarta.servlet.*으로
  • JSP taglib은 uri="jakarta.tags.core"로 (구버전 http://java.sun.com/jsp/jstl/core 사용 금지)

5DB 연결 원리

config.properties (루트)→ 빌드 시 복사 → WEB-INF/classes→ AppConfig→ DBUtil→ 각 DAO
  • pom.xml이 빌드할 때 루트의 config.properties를 앱의 클래스패스(WEB-INF/classes)에 넣습니다. 그래서 어떤 IDE로 실행해도 같은 값을 읽습니다.
  • AppConfig가 값을 읽습니다. 같은 이름의 환경변수가 있으면 환경변수가 우선합니다.
  • DBUtil.getConnection()이 그 값으로 MySQL에 접속합니다.
새 DAO를 만들 때 DBUtil.getConnection()만 쓰면 자동으로 같은 DB에 연결됩니다. 코드에 DB 주소나 비밀번호를 직접 쓰지 마세요.
DAO 예시
try (Connection conn = DBUtil.getConnection();
     PreparedStatement pstmt = conn.prepareStatement(sql)) {
    ...
}
