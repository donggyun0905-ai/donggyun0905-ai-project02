# 스펙 오디세이 (Spec Odyssey) — 요구사항 명세서 (총정리본 v2)

> **핵심 정체성**: 단순 스펙 "진단"이 아니라, 사용자가 나아갈 **"길(여정)"을 제시**하는 서비스.
> 진단 → 다음 목적지 제시(자격증·프로젝트) → 매일 그 길을 걷게 함(일일 미션) 의 여정 구조가 중심.
> 스택: JSP / Servlet / DB (+ AI API) · 목표: 기술 학습·경험 · 기간: 4주 이내(단기)

## 0) 문서 개요

- **목적**: 스펙 오디세이에 "있어야 하는 요구사항"을 총정리하고, 우선순위로 구현 순서를 잡음.
- **우선순위 표기**
  - `[필수]` — 이번 프로젝트에서 반드시 완성할 목표 범위(핵심 여정 루프 + 팀이 정한 차별화 기능).
  - `[권장]` — 완성도·차별점을 크게 높이는 기능. 필수 완료 후 시간 되면 추가.
  - `[선택]` — 여유 있을 때. 없어도 프로젝트 성립.

> `[필수]` 범위가 넓으므로, 4주 안에서는 **핵심 여정 루프(가입→프로필→분석→길 제시→대시보드 기본)를 먼저 완성**한 뒤 나머지 필수(데이터 인사이트·일일 미션·면접관 뷰)를 붙이는 순서 권장(7·8절 참고).

## 용어 정의

| 용어 | 의미 |
| --- | --- |
| 여정(오디세이) | 진단에서 끝나지 않고 "다음에 뭘 할지" 순서 있는 길을 제시하는 이 서비스의 핵심 컨셉 |
| 격차 분석 | "현재 나 vs 목표 직무 요구사항"의 차이(충족/부족)를 비교하는 것 |
| 길 제시(로드맵) | 부족한 부분을 채우는 순서 있는 단계(①자격증→②프로젝트→③스킬)를 제시하는 것 |
| 직무 발굴 | 희망 직무가 없는("아직 모르겠음") 사용자에게 어울리는 직무를 찾아주는 것 |
| 여정 지도 | 로드맵 진행 상황을 지도/항해도처럼 시각화한 화면 |
| 데이터 인사이트 | 수집한 채용 데이터를 집계·가공해 보여주는 분석(또래 비교·시계열 등) |
| 시맨틱 매칭 | 키워드 일치가 아닌 의미 유사도(임베딩)로 스킬↔역량을 연결하는 것 |
| 캐싱 | AI 분석·API 결과를 DB에 저장해 재호출을 줄이는 것 |
| 공유 링크(면접관) | 지원자가 발급한 비공개 링크로만 면접관이 이력을 읽는 방식 |

## 4) 제약 사항

- 환경: Java, JSP/Servlet, Tomcat.
- DB: **MySQL 8.0 이상** (팀 확정).
- AI 호출은 서버(Servlet)에서 수행(키 노출 방지), JSON 파싱은 Gson/Jackson.
- 서류 업로드는 multipart 처리 필요(Servlet `Part` 또는 Commons FileUpload).
- 데이터 출처(직무 요구스펙·코테 문제·트렌드 기술)는 5절 기술 결정 사항 참고.
- AI 멘토 챗봇은 이번 범위에서 보류(추후 논의).
- 기간 4주 → `[필수]` 우선 완성 원칙.

## 5) 기술 결정 사항 (Technical Decisions)

### TD-1. AI 구조 — 하이브리드 + 임베딩 시맨틱 매칭

- **하이브리드 방식** 채택. 격차 분석은 **규칙기반**(직무 요구스펙 DB 대조)으로 정확하게 처리, 로드맵 설명·추천 이유·직무 추천·첨삭 등 자연어 영역은 **LLM API** 담당.
- **임베딩 기반 시맨틱 매칭** 적용. 사용자 스킬과 직무 요구 역량을 키워드 일치가 아닌 **의미 유사도(벡터)**로 매칭 (예: "파이썬 데이터 처리" ↔ "Pandas/ETL" 연관).
- 딥러닝 자체 학습은 제외(4주·인프라 범위 밖).
- **임베딩 생성 방식: 로컬 (팀 확정)** — Java 환경이므로 DJL + ONNX Runtime으로 ko-sroberta-multitask(768차원) 사용. MVP는 "DB 저장 + 직접 계산".
- LLM 벤더는 추후 결정(스키마 영향 없음).

### TD-2. 데이터 수집 — 파이프라인 구조

- **사용자 입력 데이터**: 폼으로 받아 DB 저장.
- **직무별 요구 스펙(기준 데이터)**: 초기엔 AI 보조로 수기 구축 → 이후 **워크넷(고용24) Open API + 주기적 재수집**으로 확장·갱신.
  - 워크넷 API는 공공데이터라 무료, 인증키 신청 필요, 결과 XML(UTF-8).
- **크롤링은 공식 API가 없는 소스에만 최후수단**으로. (워크넷은 API 사용, 크롤링 금지)
- **표준 스키마로 정규화** 단계 필수. 수기·API·크롤링 세 소스의 형식이 다르므로 하나의 통일 스키마로 정제 후 적재.
- **보여주는 방식**: 원본 나열이 아니라 **집계·시계열로 가공**.
- **"모든 직무" 대응 = On-demand 수집 + 캐싱**: 사용자가 입력한 직무명으로 필요할 때 워크넷 API를 실시간 호출해 요구스펙을 추출·분석. 인기 직무는 사전 수집, 드문 직무는 요청 시 수집 후 캐싱.
- **범위: IT 계열 직무로 한정 (팀 확정)** — 초기 대상 15~20개 직무.
- **대기업 데이터 커버리지 한계**: 워크넷/고용24는 정부 공식이라 신뢰성은 높지만 지역 중소기업·공공 위주라 대기업 공고가 적음.
  - **채택: 대안 B** — 대기업 요구스펙은 LLM이 "해당 직무 대기업의 일반적 요구 역량"을 생성해 보완하되 **"예시적 추정"으로 명시**.
  - 병행: 서비스에 데이터 출처 한계를 명시(투명성).
- **재수집 주기 (팀 확정)**: 워크넷 주 1회(일요일 새벽 배치), On-demand 캐시 TTL 7일, 시계열 스냅샷 매월 1일, 트렌드 기술 일 1회, LLM 추정 데이터는 수동 트리거.

### TD-3. 코테 문제 소스

- **세 소스 병행**: ① AI 생성(난이도 맞춰 문제 생성, 정답 검증 로직 필요) ② 링크 추천("오늘의 추천: 백준 N번" 링크만 제시, 콘텐츠 복제 X) ③ 오픈 라이선스 문제셋.
- **저작권 크롤링 금지**: 채용 코테·플랫폼 문제 지문을 가져오는 방식은 저작권/약관 위반 소지로 제외.
- **대화형 AI 멘토 챗봇은 이번 범위에서 제외(보류)**. 문제 생성은 "버튼 → 결과 표시" 방식으로 충분.

### TD-4. 확장성 고려 설계 (지금 단순, 나중에 확장)

- 면접관 접근은 이번엔 로그인 없이 공유 링크만(FR-14·85). 단, **DB에는 확장 대비 필드를 미리 마련**:
  - 사용자 테이블에 `user_type`(지원자/면접관) 컬럼을 지금부터 두되, 현재는 전부 '지원자'로만 사용.
- **원칙**: 당장 안 쓰더라도 확장이 예상되는 구조(유형 구분, 공유 링크 토큰 테이블 등)는 **필드/테이블만 미리 설계**해 두고 기능은 나중에.

### TD-5. 레벨 / 스코어링

**(a) 등급 — 총점 상한 없는 게임식 누적 점수**

| 신호 | 포인트 | 비고 |
| --- | --- | --- |
| 길(로드맵) 진행률 | 단계 완료당 +100 | 여정 서비스의 핵심이라 배점 최상 |
| 코테 정답률·정답 | 정답당 +10~30(난이도별) | 실력 직접 지표 |
| 푼 문제 수 | 문제당 +5 | 꾸준함(누적) |
| 프로젝트 서류 등록 | 서류당 +30 | 경험 |
| 자가진단 | 초기 1회 +0~50 | 신뢰도 낮아 baseline 보정용만 |

**(b) 등급 구간**

| 누적 점수 | 등급(호칭) |
| --- | --- |
| 0 ~ 499 | 비기너 (뉴비 항해사) |
| 500 ~ 1499 | 취준생 (견습 항해사) |
| 1500 ~ 2999 | 실전러 (정식 항해사) |
| 3000 ~ 4999 | 취뽀 임박 (선장) |
| 5000 ~ | 취뽀 (전설의 선장) |

**(c) 문제 난이도 매칭** — 우리 등급 ↔ 외부 문제 레벨(프로그래머스 Lv 등) 매핑. 등급이 오를수록 더 높은 레벨 문제를 추천/생성. (예: 비기너→Lv1, 실전러→Lv2~3)

**(d) 순환 참조 방지 (baseline)** — "길 진행률"이 등급에 영향을 주고 등급이 다시 길·난이도를 정하는 구조라 서로 물림. 신규 유저는 길 진행률 0이므로, **첫 등급은 자가진단 + 서류/스펙만으로 산정**하는 기준점을 둠.

## 6) 사용자 흐름 (여정 중심)

```
[회원가입/로그인]
    ↓
[프로필 입력] — 희망직무 있음? ── 있음 → [격차 분석]
    │                          └ 없음 → [직무 발굴] → 직무 선택 → [격차 분석]
    ↓
[길 제시] ★ 순서 있는 로드맵 (①자격증 → ②프로젝트 → ③스킬 …)
    ↓
[대시보드] 완성도·격차·여정지도·데이터 인사이트 + 마감 D-day
    ↓
[매일] 일일 코테 미션 + 우측 트렌드 기술 사이드바
    ↓
[서류 보관함] 프로젝트 서류 저장 (추후 챗봇이 읽음)
    ↓
(평가자) 지원자가 준 **공유 링크**로 접속 → 면접관 뷰(타임라인·비교·적합도·성장 잠재력) 읽기 전용
```

## 7) 우선순위별 범위

### [필수] — 이번에 반드시 완성 (핵심 여정 + 차별화 기능)

- 회원/인증: FR-11·12·13·14 (14는 면접관 로그인 없음 + DB 확장 필드만 마련)
- 프로필 입력: FR-21·22·23·24·25
- AI 분석 + 길 제시: FR-31·32·34·38·39 (격차 분석·로드맵·직무 발굴)
- 대시보드/시각화: FR-41~48 (완성도·격차·여정 지도·데이터 인사이트 전체)
- 일일 미션 + 기술 사이드바: FR-51~55 (전체)
- 면접관 뷰: FR-81·82 (타임라인·비교) + FR-85 (공유 링크 접근)
- 예외 처리: FR-111·112 (AI·외부 API 실패 대응)

> "가입 → 이력 입력 → 진단 → 길 제시 → 대시보드"가 최소 여정 루프.

### [권장] — 시간 되면 추가

FR-33(로드맵 이유), FR-35(직무 요약), FR-36(완료 체크), FR-37(캐싱), 서류 보관함 FR-61·62, 알림/D-day FR-71·72, 적합도 스코어링 FR-83, 첨삭 FR-91·92, FR-86(공유 링크 만료), FR-113(데이터 없는 직무 보완), FR-114(빈 상태 안내)

### [선택] — 여유 있을 때

FR-63·64(서류 연결·챗봇 읽기), FR-73(이메일 알림), FR-84(성장 잠재력), FR-101·102(AI 역량 리포트), FR-115(온보딩), AI 멘토 챗봇(추후 논의)
