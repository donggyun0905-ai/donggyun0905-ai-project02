# 자를 하나로 — 요구 수준 4단계 통일, 전문가 증빙을 아카이브 글로, 유형별 분류

날짜: 2026-10-14
관련 커밋: `bb30a00` → `aab6a07` → `41b87fa` → `b865d10`
마이그레이션: `sql/40_alter_job_required_skill_4tier.sql` (한 번만 실행)
테스트: 1,060 → **1,094개** (+34)

---

## 1. 개요

발표가 끝나고 미뤄 뒀던 것을 했다. 시작은 한 줄짜리 질문이었다.

> "기술에 대해 우리가 입문 기초 중급 심화로 지정하지 않았나? 몇몇 기능은 3개로만 되어
> 있는 것 같고 인사이트에 미지정도 있다."

파 보니 **같은 서비스 안에 "기술을 어디까지 해야 하는가"를 재는 자가 셋**이었다.

| 척도 | 컬럼 | 값 | 어디에 |
| --- | --- | --- | --- |
| 로드맵 티어 | `ROADMAP_STEP.tier` | ENTRY · CORE · ADVANCED · EXPERT | 로드맵, 직무 벤치마크 |
| 직무 요구 수준 | `JOB_REQUIRED_SKILL.required_level` | BASIC · INTERMEDIATE · ADVANCED | 인사이트 히트맵 |
| 사용자 숙련도 | `USER_SKILLS.proficiency` | BEGINNER · INTERMEDIATE · ADVANCED | 프로필, 면접관 화면 |

셋 다 `ADVANCED`를 쓰는데 뜻이 달랐다. 히트맵의 "심화"와 로드맵의 "심화"가 같은 것으로
읽혔고, 격차 분석에서는 같은 `ADVANCED`를 "고급"이라 불렀다.

그래서 오늘 한 일은 **자를 하나로 맞춘 것**이고, 그러고 나니 할 수 있게 된 것들을
이어서 했다.

## 2. 요구 수준을 티어와 같은 4단계로 (`bb30a00`)

### 2-1. 값을 손으로 정하지 않았다

처음에는 "217줄을 하나씩 배정해야 하나" 싶었다. 그런데 **원래 있던 두 칸을 합치니
4단계가 그대로 나왔다.**

| 지금 (두 칸) | → | 결과 | 줄 수 |
| --- | --- | --- | --- |
| 우대(PREFERRED) | | **입문** 읽고 정리하면 된다 | 103 |
| 필수 + BASIC/값 없음 | | **핵심** 프로젝트에 써 봐야 한다 | 27 |
| 필수 + INTERMEDIATE | | **심화** 깊이 다뤄 봐야 한다 | 51 |
| 필수 + ADVANCED | | **전문가** 남에게 설명할 수 있어야 한다 | 23 |

각 단계의 뜻은 **제출물이 정한다** — 입문은 공부노트 PDF, 핵심은 프로젝트 등록,
심화는 기존 프로젝트 업그레이드, 전문가는 기술 설명 글.

`ADVANCED`가 원래 없던 직무 6개만 전문가 칸이 비어서, 정체성 기술을 하나씩 올렸다.

```
백엔드 Spring Boot · 서버 Linux · 보안 엔지니어 SIEM
정보보안 IAM · IT 기획 Agile/Scrum · 서비스 기획 UI/UX Design
```

보안 쪽 셋이 겹치지 않게 뒀다 — 모의해킹은 Metasploit·Burp Suite 를 그대로 두고,
보안 엔지니어는 SIEM(관제·운영), 정보보안 담당자는 IAM(계정·권한)으로 나눴다.
결과: 18개 직무 모두 전문가 1개 이상.

### 2-2. 미지정이 사라졌다

값이 없던 15줄 중 **13줄이 부하 테스트 잔재**였다. 운영 DB의 `SKILL`에
`초대량스킬1_700007988772000` 같은 이름이 14개 남아 `API 개발자` 요구 기술로 붙어
**화면에 그대로 나오고 있었다.** 보유 사용자 0명 · 로드맵 단계 0건 · 격차 분석 항목 0건을
확인하고 논리 삭제했다. 남은 2줄(`DNS`·`TCP/IP`, NCS 수집 실제 데이터)은 규칙대로 핵심.

### 2-3. 순서에만 반영했다 — 단계 수는 그대로

요구 수준은 **표시 말고는 아무 데도 쓰이지 않고 있었다.** `RoadmapGenerator`·
`RoadmapService`·`GapAnalysisService` 모두 참조가 0회였다. 그래서 Git(기초만 요구)에도
전문가 단계가 깔렸다 — `ROADMAP_STEP`의 티어 분포가 CORE 179 / ADVANCED 179 /
EXPERT 179로 **정확히 같은 것**이 그 증거다.

통일하고 나서 "요구 수준에서 로드맵을 끊을까"를 따져 봤다. 숫자를 재 보니
**한 라운드가 20단계에서 7.5단계로 62% 줄어든다.** 기존 사용자의 로드맵 모양이 크게
달라지는 변경이라 **순서에만 반영하고 끊지는 않기로** 했다(팀 결정).

부족 기술을 요구 깊이 순(전문가 → 입문)으로 줄 세운다. 지금 데이터는 우대가 모두
입문이라 수준만으로도 필수가 앞서지만, 관리자가 "필수인데 입문"을 넣을 수 있어
중요도를 보조 기준으로 남겼다.

### 2-4. 값이 다시 어긋나지 않게

- **관리자 화면이 자유 입력이었다.** 그래서 한글 `"심화"`가 그대로 저장돼 히트맵이 못 읽는
  값이 생겼다(테스트 픽스처에 그 흔적이 남아 있었다). 선택지 4개로 바꾸고, POST를 직접
  보내도 뚫리지 않게 `AdminReferenceService.checkRequiredLevel`에서 한 번 더 본다.
- **`RequiredLevelVocabularyTest`** — 시드에 옛 어휘가 한 줄이라도 남으면 빌드가 깨진다.
  남으면 **새로 만든 DB만 조용히 옛 값을 갖고** 화면에서 "미지정"으로 보인다. 찾기 어렵다.
  한 줄을 `BASIC`으로 되돌려 검사가 잡는 것을 확인했다.
- `InsightService`의 라벨 표 두 개(`LEVEL_LABELS`·`TIER_LABELS`)를 하나로 합쳤다.
  같은 자가 됐으니 표도 하나여야 한다. 못 읽는 값은 "심화"로 둘러대지 않고 미지정으로
  모은다 — **데이터가 없는 것과 깊이를 요구하는 것은 다르다.**

### 2-5. 마이그레이션 주의

`sql/40`은 **한 번만 실행한다.** `ADVANCED`가 옛 값이자 새 값이라 두 번 돌리면
심화가 전문가로 한 칸씩 밀려 올라간다. 옛 어휘가 남아 있을 때만 돌도록 `@needs_convert`로
막아 뒀고, 변환은 나눠 돌리면 안 되므로(INTERMEDIATE → ADVANCED 로 바꾼 행이 바로
다음 문장의 "ADVANCED → EXPERT"에 다시 걸린다) **한 번의 `UPDATE … CASE`**로 끝낸다.

## 3. 글쓰기 등급 제한을 풀었다 (`aab6a07`)

아카이브 글쓰기가 상위 두 등급(개척자·오디세이아)만 가능했다. **문을 잠그는 대신
무엇을 증명했는지 보여 주는 쪽**으로 바꿨다 — 읽는 사람이 판단하면 된다.

```
등급        이미 나오고 있었다 (금색 배지)
전문가 기술  새로 붙였다 — "Java 전문가" (청록 배지)
```

목록은 자리가 좁아 2개까지 + `+N`, 상세는 전부. 글 목록 한 쪽에 작성자가 여럿이라
한 사람씩 물으면 N+1이 된다 — `findExpertSkillNamesByUserIds`가 한 번에 가져오고,
목록·검색·북마크가 모두 거쳐 가는 `withPreview` 한 곳에 붙여서 빠지는 길이 없다.

게이트가 없어지면서 죽은 코드가 생겨 같이 걷어냈다(`topTiers`·`writerTiers`·
`tierForScore`·`WRITER_TIER_COUNT`·두 서블릿의 요청 속성·두 화면의 잠금 분기).
`canWrite` 메서드는 남겼다 — 화면 여러 곳이 묻고 있고, 나중에 조건을 다시 걸면 여기
한 곳만 고치면 된다.

> 작업 중 `prepare(req, userId)`의 `try` 블록이 통째로 비어 컴파일이 깨졌다 —
> 지운 두 줄이 그 안의 전부였다. 메서드에서 `userId`와 `SQLException`을 걷어냈다.

## 4. 전문가 증빙을 PDF에서 아카이브 글로 (`41b87fa`)

### 4-1. 왜 바꿨나

"굳이 PDF여야 할까? 디자인이나 ERD도 넣고 싶은데" 라는 질문에서 시작했다.
확인해 보니 **설계는 원래 이거였다** — `TECH_ARTICLE.roadmap_step_id`(UNIQUE)와
`source_type='ROADMAP_EXPERT'`가 그걸 위해 있는데 **잇는 코드가 없었다.**

PDF의 문제 셋:

- **본인 말고 아무도 못 봤다.** "남에게 설명할 수 있다"가 이 단계의 뜻인데 아무도 안 읽었다.
- **판정이 추출된 텍스트만 봤다.** ERD를 열 장 넣어도 글자 수가 모자라면 미통과고,
  그림 한 장 없이 800자만 채우면 통과였다.
- 글 쓰고 → PDF로 내보내고 → 올리기. **한 단계가 더 있었다.**

아카이브 편집기는 이미 사진 업로드(합쳐 10MB) · 이미지 링크 · 유튜브 · 코드 블록을
지원한다. 글자 수에 이미지·코드·링크는 세지도 않는다.

### 4-2. 판정 기준을 두지 않았다 (팀 결정)

글자 수·기술명 횟수·링크 유무 같은 숫자를 **우리가 정하지 않는다.** 쓰는 행위가 증빙이고,
글이 공개되므로 읽는 사람이 판단한다. 아카이브 자체 규칙(제목 필수, 본문 최대 길이)만
적용된다.

### 4-3. 흐름

```
로드맵 EXPERT 단계 → [기술 설명 글 쓰기] → /spec-archive/write?stepId=N
→ 편집기(사진·ERD·코드) → 올리면 글 저장 + 단계 완료가 한 트랜잭션
```

둘 중 하나만 되면 글만 있고 단계는 미완이거나 그 반대가 된다. `SpecArchiveService.create`의
본문을 `insertArticle(Connection, …)`로 빼서 자유 글과 전문가 단계 글이 같은 저장 과정을
쓰게 했다.

### 4-4. 숨어 있던 구멍 셋을 같이 막았다

- **아카이브 목록 쿼리가 `source_type='ARCHIVE_TIP'`으로 못 박혀 있었다.** 전문가 단계
  글을 만들어도 **어디에도 안 보였을 것이다.** `IN (ARCHIVE_TIP, ROADMAP_EXPERT)`로 바꿨다.
- **`submitSkillNote`가 EXPERT를 계속 받으면 구멍이 된다.** 예전 화면이나 직접 POST로
  **글 없이 전문가 단계를 완료**할 수 있다. 이제 ENTRY(공부노트)만 받는다.
- **완료를 취소하고 다시 쓰면 터진다.** `roadmap_step_id`에 UNIQUE가 걸려 있어 두 번째
  INSERT가 깨진다. 이미 쓴 글이 있으면 새로 만들지 않고 **그 글로 단계만 다시 완료**한다 —
  쓴 글을 덮어쓰거나 두 벌로 만들지 않는 쪽이 맞다. 고치려면 아카이브에서 그 글을 고친다.

`SkillProofGrader.gradeExpertArticle`은 **남겼다** — ARTICLE_UPDATE(기술 글 보강)
단계가 아직 같은 규칙을 쓴다. 지웠으면 그쪽이 깨졌다.

## 5. 기술 유형별 분류 (`b865d10`)

`TECH_ARTICLE.skill_id`가 있었는데 아무도 안 읽고 있었다. 전문가 단계 글이 그 값을
채우기 시작하면서 쓸 수 있게 됐다.

- 목록 위에 **유형 거르개** — `SKILL.category` 12종. 글이 있는 유형만 많은 순으로.
  열두 개를 다 늘어놓으면 대부분 0이라 자리만 먹는다. 기술을 안 고른 글은 "기타"로.
- 글 카드 앞에 **기술 이름 칩**. `SKILL`을 LEFT JOIN 해서 한 번에 가져온다.
- **자유 글도 기술을 고를 수 있게** 했다(선택). 안 그러면 자유 글이 전부 기타에 쌓여
  거르개가 반쪽이 된다.

### 손이 많이 간 곳 셋

- **COUNT 질의에도 같은 LEFT JOIN이 필요했다.** 유형 조건이 `sk.category`를 보는데
  COUNT에는 조인이 없었다. 그냥 뒀으면 **목록은 나오는데 건수만 깨져 쪽 번호가 어긋났을**
  것이다. `COUNT_FROM` 상수로 묶었다.
- **검색은 `?` 자리 번호가 밀린다.** SELECT 절의 `relevance`가 하나를 먼저 쓰고,
  유형이 그다음, WHERE의 MATCH가 그다음이다. `bindCategory`가 다음 번호를 돌려주게 해서
  손으로 세지 않게 했다.
- **유형 이름에 공백이 있다**("프로그래밍 언어"). 주소에 그냥 붙이면 끊기므로
  `c:url` + `c:param`으로 만든다. `JspEscapingTest`가 href의 `${…}`를 잡아내서
  `c:out`으로 감쌌다 — **`c:url`이 URL 인코딩, `c:out`이 HTML 이스케이프(`&` → `&amp;`)**로
  둘 다 필요하다.

`mapRow`는 질의마다 SELECT 열이 달라서(관리자 목록 등은 조인이 없다) **열이 있을 때만
읽는다.**

## 6. 오늘 낸 실수 셋

### 6-1. `List.of(...).indexOf(null)`이 NPE를 던진다

정렬에 쓸 `depthOf`를 이렇게 썼다.

```java
int index = SKILL_TIER_ORDER.indexOf(requiredLevel);   // SKILL_TIER_ORDER 는 List.of
```

`List.of`는 null을 허용하지 않아 `indexOf(null)`에서 터진다. 직무 요구 기술에 없는
기술(프로필에서 들어온 것)은 수준이 null로 와서 **실제로 걸렸고**,
`GapAnalysisServiceTest`가 잡았다. 회귀 테스트를 남겼다.

### 6-2. 정규식 그룹 번호를 잘못 써 시드 202줄을 날렸다

이름 있는 그룹과 번호 그룹을 섞어 쓰다가 `group(5)`가 뒷부분이 아니라 옛 값이었다.
결과가 `'ADVANCED'INTERMEDIATE` 처럼 되어 파일이 깨졌다. `git checkout`으로 되돌리고
**이름 있는 그룹만** 써서 다시 했다. 변환 뒤 줄 수(202)와 "값 외에는 안 바뀜"을
`git diff`로 확인했다.

### 6-3. 같은 teardown 실패를 네 번째로 봤다

점수를 한 번이라도 적립하면 `ScoreService`가 `USER_SCORE_SUMMARY` 한 줄을 만든다.
테스트가 직접 만든 게 아니라 빠뜨리기 쉽고, FK(RESTRICT)로 `USERS` 하드 삭제를 막는다.
10/06 · 10/07 · 10/08에 이어 **네 번째 같은 모양**이라 `TestFixtures.hardDelete`에
넣었다 — `SPEC_SCORE_HISTORY` 옆자리다.
