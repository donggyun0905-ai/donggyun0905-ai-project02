추천 1순위: 발표에서 "알고리즘을 썼다"고 설명하기 좋은 것

1. 기술 선수관계 그래프: 위상 정렬(Kahn) + DFS 순환 검사

지금 상태: 로드맵 순서는 "필수냐 우대냐, 몇 단계냐"로만 정합니다(RoadmapGenerator). "Spring 전에 Java", "Docker 전에 Linux" 같은 선수관계는 없습니다.
바꾸면:
SKILL_PREREQUISITE(skill_id, prereq_id) 테이블을 만들고, 로드맵을 만들 때 위상 정렬로 순서를 정합니다.
관리자가 선수관계를 추가할 때 DFS로 순환(A→B→A)을 막습니다. 관리자 기준 데이터 화면(/admin/reference)에 붙이면 됩니다.
효과: "왜 이 순서냐"는 질문에 그래프로 답할 수 있습니다. 말씀하신 DFS가 가장 자연스럽게 들어가는 자리입니다.

2. 간격 반복 학습(SM-2 알고리즘)으로 복습 주기를 사람마다 다르게

지금 상태: RoadmapReviewService의 복습 주기가 입문 30일, 핵심 60일, 심화 90일, 전문가 120일로 고정입니다.
바꾸면: 복습을 제출할 때 "쉬웠다 / 보통 / 어려웠다"를 받고, Anki가 쓰는 SM-2 공식으로 기술마다 다음 복습일을 계산합니다. 테이블에 ease_factor 컬럼 하나만 추가하면 됩니다.
효과: "잊어버리는 속도에 맞춘 복습"이라는 근거가 생기고, 계산식이 짧아서 테스트하기도 쉽습니다.

3. D-day까지 무엇을 할지: 0/1 배낭 문제(DP)

지금 상태: D-day 화면은 일정만 보여 줍니다.
바꾸면: 남은 일수(용량) 안에서 로드맵 단계들(소요 일수 = 무게, 점수·필수 여부 = 가치)을 골라 "이 기간에 이것부터 하면 점수가 가장 많이 오른다"를 추천합니다.
효과: 기존 점수 체계(StepPointCalculator)를 그대로 가치로 쓸 수 있습니다.

4. 기술 : 하이브리드 검색 (편집 거리·n-gram + 임베딩 점수를 RRF로 합치기)
넣을 곳 : SkillMatcher
이유 : 지금은 정확 일치 → 편집 거리 → 임베딩을 차례로 시도합니다. 점수를 합치면 "리액트"와 "React.js" 같은 경계 사례가 안정적으로 잡힙니다.

5. 기술 : 함께 익힌 기술 추천 (자카드 유사도, 동시 출현 빈도)
넣을 곳 : 대시보드 "다음에 할 일"
이유 : "같은 직무를 목표로 한 사람들이 Java 다음에 많이 익힌 기술"을 보여 줍니다. 회원 데이터로 하는 간단한 협업 필터링입니다.

6. 기술 : 급상승 기술 감지 (EWMA, z-score)
넣을 곳 : JobSkillTrendService
이유 : 단순 공고 수가 아니라 평소보다 얼마나 튀었는지로 "급상승" 배지를 붙입니다.

7. 기술 : 토큰 버킷 + 서킷 브레이커
넣을 곳 : GroqLlmClient, ExternalApiClient
이유 : Groq 무료 한도, GitHub 403, 고용24 장애가 날 때 계속 재시도하지 않고 바로 대체 동작으로 넘어갑니다. 이번 점검 로그에서도 GitHub 403이 반복됐습니다.

8. 기술 : MySQL FULLTEXT (ngram 파서)
넣을 곳 : 스펙 아카이브 검색, 관리자 회원 검색
이유 : 지금 LIKE '%…%' 검색은 인덱스를 못 탑니다. 한글은 ngram 파서로 해결됩니다.
