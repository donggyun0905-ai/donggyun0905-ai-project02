## 2. 톰캣 11 EL 사건 (`3e9c2c9`, `d211d65`)

### 2-1. 무슨 일이었나

면접관 "이력 보기"(`/share/{토큰}`) 화면 전체가 500이었다. 그런데:

- 팀원 4명 화면에서는 정상
- 테스트 846개도 전부 통과
- 로드맵·대시보드 등 다른 화면은 멀쩡

톰캣 로그를 보니 원인은 한 줄이었다.

```
interviewer-view.jsp (행: [280]) [${empty view.activity or view.activity.empty}]이(가)
유효하지 않은 표현식(들)을 포함하고 있습니다:
jakarta.el.ELException: 표현식을 파싱하지 못했습니다
```

`empty`는 **EL 예약어**다. `.empty`를 속성 이름으로 쓸 수 없다. 톰캣 11(EL 6.0)은 표현식 자체를
파싱하지 못하고, 10.1(EL 5.0)은 통과했다 — **팀원 중 나만 11이었다.**

애초에 내가 `History.empty()`를 둔 것이 틀렸다. Tomcat 11의 `RecordELResolver`가 `isX()`를 안 찾는다는
10/6의 교훈을 적용해 `x()` 형태를 추가한 것인데, `empty`는 그 이름 자체를 EL이 속성으로 읽을 수 없다.
화면은 `totalEvents == 0`을 보게 바꾸고, 쓸 수 없는 접근자는 지웠다.

> seongwon도 같은 버그를 독립적으로 고쳤다(`09beddd`, 커밋 메시지 "지원자 이력 화면 500").
> 결론이 `totalEvents == 0`으로 완전히 같아서 충돌 없이 겹쳤다. 다만 **10.1에서도 터졌다는 뜻**이라,
> "11에서만 깨진다"는 내 추정보다 범위가 넓었다.

### 2-2. 왜 테스트가 못 잡았나 — 그리고 이제 잡는다

JSP는 요청받는 순간 컴파일된다. 그래서 빌드와 테스트는 멀쩡하고 **그 화면을 실제로 열어 본 사람만** 죽는다.
열어 본 사람이 나 혼자면 아무도 모른다.

그래서 `JspCompileTest`를 넣었다. 45개 JSP 전부를 Jasper로 미리 컴파일한다.

```java
JspC jspc = new JspC();
jspc.setUriroot(WEBAPP.toAbsolutePath().toString());
jspc.setCompile(false);   // 자바 소스 생성까지 — EL·태그 검증은 그 단계에서 끝난다
jspc.setFailOnError(true);
jspc.setClassPath(System.getProperty("java.class.path")); // jar 안의 TLD를 찾게
jspc.execute();
```

핵심은 **pom에서 `tomcat-jasper`를 11.0.25로 고정**한 것이다. 로컬 톰캣을 쓰면 10.1인 팀원 환경에서는
그대로 통과해 버린다. 버전을 박아 두면 **10.1을 쓰는 사람이 돌려도 11 기준으로 걸린다.**

```xml
<dependency>
    <groupId>org.apache.tomcat</groupId>
    <artifactId>tomcat-jasper</artifactId>
    <version>11.0.25</version>
    <scope>test</scope>
    <exclusions>
        <!-- jakarta.servlet-api 6.0.0과 같은 패키지라, 둘이 같이 있으면 어느 쪽이 먼저
             잡히는지에 따라 다른 테스트가 흔들린다 -->
        <exclusion>
            <groupId>org.apache.tomcat</groupId>
            <artifactId>tomcat-servlet-api</artifactId>
        </exclusion>
    </exclusions>
</dependency>
```

**검사가 실제로 잡는지 확인했다.** 고친 줄을 되돌려 돌려 보니 정확히 그 줄을 짚었다.

```
interviewer-view.jsp (line: [280], column: [20]) [${empty view.activity or view.activity.empty}]
contains invalid expression(s): [jakarta.el.ELException: Failed to parse the expression ...]
Generation completed with [1] errors
```

주의: **JspC는 오류가 있어도 종료 코드 0을 준다**(`-failFast`를 줘도 마찬가지였다). 그래서
exec 플러그인으로 돌리면 빌드가 실패하지 않는다. JUnit에서 `execute()`가 던지는 예외를 받아야 한다.

### 2-3. 같이 메운 빈틈 — `RecordElCoverageTest`

10/6에 만든 record EL 전수 검사가 `${a.b.c}`에서 **첫 조각만** 보고 있었다. `${view.education.gpaText}`에서
`education`만 잡혀 `gpaText`는 검사에서 통째로 빠졌다. 표현식 안의 모든 조각을 보게 넓혔다.
(넓힌 뒤 새로 걸린 건 없었다 — 중첩 속성들이 record가 아니라 class였다.)

## 3. 로드맵 생성이 중복키로 500이던 문제 (`3855534`)

2절의 로그 조사에서 나온 10/6 기록이다.

```
java.sql.SQLIntegrityConstraintViolationException:
  Duplicate entry '5053' for key 'roadmap.uk_roadmap_gap_analysis_id'
  at com.specodyssey.dao.RoadmapDao.insert(RoadmapDao.java:45)
  at com.specodyssey.service.RoadmapGenerator.lambda$generate$1(RoadmapGenerator.java:120)
```

`ROADMAP.gap_analysis_id`는 UNIQUE(한 분석에 로드맵 하나)다. 중복 가드는 10/2부터 있었는데도 터졌다.
읽어 보니 구조가 이랬다.

```
① 이 분석의 로드맵이 있나? (조회)
② 라운드 기술 고르기, 자격증 고르기, 프로젝트 안내 문구 만들기  ← LLM 호출, 수 초
③ INSERT
```

①과 ③ 사이에 **수 초가 비어 있다.** 그 사이에 들어온 두 번째 요청(버튼 두 번 클릭)이 같은 ①을 통과하면
둘 다 ③에 도달해 뒤쪽이 깨진다. 접근 로그에도 11:54:45(302)와 11:54:47(500)이 2초 차이로 남아 있었다.

LLM 호출을 트랜잭션 안으로 넣을 수는 없다(claude.md: 외부 API가 느리거나 실패해도 DB 커넥션을 물고
있으면 안 된다). 그래서 **두 겹으로** 막았다.

```java
// 겹 1 — INSERT 직전에 같은 커넥션으로 다시 본다. 바깥 확인은 LLM 호출 전이라 이미 낡았을 수 있다
RoadmapDto raced = roadmapDao.findByGapAnalysisId(conn, analysis.getId());
if (raced != null) { /* 그걸 대표로 세우고 그 id를 쓴다 */ }

// 겹 2 — 그래도 중복키가 나면, 먼저 들어간 쪽이 만든 로드맵을 쓴다
} catch (SQLIntegrityConstraintViolationException e) {
    Long recovered = recoverFromDuplicateGapAnalysis(userId, analysis.getId(), e);
    if (recovered == null) {
        throw e; // 다른 제약 위반이면 삼키지 않는다
    }
    return recovered;
}
```

사용자가 원한 건 "로드맵 하나"다. 먼저 들어간 것을 쓰는 게 맞다.

**다른 제약 위반을 삼키지 않게** 제약 이름(`uk_roadmap_gap_analysis_id`)으로 가린다. 한 트랜잭션 안에서
단계·점수도 쓰기 때문에 다른 위반이 섞여 들어올 수 있다. 문자열로 가리는 게 깨지기 쉬워서,
**MySQL이 실제로 그 이름을 담아 주는지 진짜 중복 INSERT를 해서 확인하는 테스트**를 같이 넣었다.

### 재현 테스트

경합은 보통 테스트로 못 잡는데, 이 경우는 **LLM 호출이 끼어 있다는 것 자체가 후크**였다.
`LlmClient`가 인터페이스 하나라 호출되는 순간 경쟁 로드맵을 넣을 수 있다.

```java
RoadmapService racing = new RoadmapService(new ProjectIdeaService(new LlmClient() {
    @Override
    public <T> T completeJson(String prompt, Class<T> type) {
        if (plantedIds.isEmpty()) {
            plantedIds.add(insertCompetingRoadmap()); // 먼저 들어온 요청이 만든 로드맵
        }
        return type.cast(new ProjectIdeaService.ProjectIdea("테스트 프로젝트", "테스트용 고정 설명"));
    }
}));
Long result = racing.generate(userId);
assertEquals(plantedIds.get(0), result, "먼저 만들어진 로드맵을 그대로 써야 한다");
```

고친 것을 되돌려 돌려 보니 **10/6과 똑같은 메시지로** 실패했다
(`Duplicate entry '7830' for key 'roadmap.uk_roadmap_gap_analysis_id'`). 두 겹을 하나씩 떼어 보며
각 겹이 단독으로도 막는 것까지 확인했다.

## 4. 면접관 이력 보기 (`3855534`)

### 4-1. PDF 미리보기와 "새 창에서 보기"가 안 열렸다 — 화면이 거짓말을 했다

조사 결과 **코드 버그가 아니었다.**

| 확인한 것 | 결과 |
| --- | --- |
| 등록된 이력서 | 2건, **둘 다 디스크에 파일 없음** |
| 그중 1건의 경로 | `C:\Users\PC_1M\...` — **팀원 PC에서 업로드** |
| `/share/{토큰}/resume` 응답 | 404 (정상 동작 — 파일이 없으니) |
| CSP / `X-Frame-Options` | 문제없음. `SAMEORIGIN`이고 iframe은 동일 출처 |
| 행만 남기고 파일을 지우는 코드 경로 | **없음** (업로드 실패 시 되돌리기는 올바르게 동작) |

업로드 폴더는 `user.home` 기준이라 **서버 PC마다 따로다.** 공유 DB를 쓰니 팀원이 올린 서류는 행만 남는다.
그런데 화면은 **파일명만 보고** iframe과 링크를 그렸다. 그래서 둘 다 조용히 실패했다 — 빈 네모와 404.

고친 방향: 뷰 모델이 **파일을 실제로 읽을 수 있는지** 확인하고, 없으면 이유를 알린다.

```java
public static boolean isReadable(String filePath) {
    if (filePath == null || filePath.isBlank()) {
        return false;
    }
    try {
        return Files.isReadable(Paths.get(filePath));
    } catch (RuntimeException e) {
        return false; // 경로 문자열 자체가 이 OS에서 올바르지 않은 경우(다른 PC에서 올린 서류)
    }
}
```

```java
// 파일이 없으면 PDF라도 미리보기를 켜지 않는다 — 열리지 않는 iframe만 남는다
public boolean isResumePdf() {
    return resumeFileReadable && FileStorageUtil.isPdf(resumeFileName);
}
```

화면에는 *"이 서버에서 파일을 찾을 수 없어 미리보기와 내려받기를 할 수 없습니다. 지원자에게 다시 올려
달라고 요청해 주세요."* 가 뜬다. 이력서·자소서·프로젝트 제출 서류 셋 다 같다.

> 데모할 때: **이력서를 데모하는 PC에서 다시 올려야** 미리보기가 보인다. 발표 체크리스트에 넣었다.

### 4-2. 보유 스펙이 빠져 있었다 — 아니, 섞여 있었다

자격증·어학·수상·경험은 "이력 타임라인"에 **프로젝트와 섞여 시간순으로만** 들어가 있었다. 그래서
"자격증이 몇 개인지"를 훑을 수 없었다. 프로필에는 보유 스펙 섹션이 따로 있어서 더 빠진 것처럼 보였다.

같은 데이터를 종류별로 묶은 **보유 스펙 카드**를 더했다. 타임라인은 시간순 서사, 이쪽은 훑는 용도다.

- 순서를 고정했다: 자격증 → 어학 → 수상 → 경험. `Map.of`는 순서를 보장하지 않아 묶음이 매번
  뒤바뀌었다 → `LinkedHashMap`으로 바꿨다
- 라벨을 모르는 `spec_type`도 빠뜨리지 않는다 (스키마가 자유 값이다)
- 경력은 기간(`2026-01-05 ~ 2026-02-28`), 종료일이 없으면 `~ 진행 중`, 자격증은 취득일
- 어학은 점수까지 (`TOEIC / ETS 900`)
- **새로 공개하는 값이 아니므로 공개 범위도 타임라인과 같다**(`scope_basic`). 기본 이력을 끈 링크에서
  스펙이 새지 않는 것도 테스트로 고정했다

## 5. FR-114 · FR-115 — 마지막 두 요구사항 (`3855534`)

이 둘이 53개 중 유일하게 구현 산출물이 하나도 없던 항목이었다(`/admin/design`이 그렇게 알려줬다).

### FR-114 빈 상태

화면마다 "아직 없습니다"는 있었지만(로드맵·대시보드·인사이트 등 6개 화면) **무엇을 해야 그게 채워지는지**는
아무도 알려주지 않았다. 또 하나의 일회성 문구를 더하는 대신, 사용자 상태에서 계산하는 서비스를 만들었다.

```
프로필 기본 정보 → 할 수 있는 기술 → 목표 직무 → 격차 분석 → 로드맵
```

- **첫 미완료 단계가 "지금 할 일"** 이다. 강조는 한 곳만 — 두 곳이면 무엇부터 할지 또 고민하게 된다
- 앞 단계를 건너뛴 **기존 가입자**도 자기 자리에서 이어간다(설문 없이 프로필에서 직무만 고른 사람 등)
- **다 걸은 사람에게는 아무것도 그리지 않는다.** 할 일이 없는데 카드가 남아 있으면 방해만 된다
- 기본 정보는 **전공과 학년이 둘 다** 있어야 채운 것으로 본다 — 이 둘이 없으면 추천이 전공을 반영할 수 없다

대시보드와 프로필에 공용 조각(`common/next-steps.jspf`)으로 붙였다. 프로필은 `doGet`이 아니라
`loadProfileAttributes()`에 넣었다 — 저장 실패로 폼을 다시 그릴 때도 같이 나와야 하고, 그 메서드를
네 곳에서 부른다.

### FR-115 온보딩

`OnboardingFilter`가 이미 있었지만 그건 **막는** 역할이고(설문 전에는 설문·프로필만), 왜 설문부터

## 6. 프로필에서 프로젝트를 전부 입력할 수 있게 (`4b1b43a`)

프로필의 프로젝트 칸이 받는 항목이 면접관 화면에 보이는 항목보다 적었다. DB 컬럼 기준으로 전수 대조한 결과,
**빠진 건 프로젝트 쪽뿐**이었다(기본정보·기술·스펙·학력·링크는 컬럼을 전부 받고 있었다).

| 항목 | 저장 위치 | 프로필 | 로드맵 제출 | 면접관에게 |
| --- | --- | --- | --- | --- |
| 완료 회고 | `USER_PROJECTS.retrospective` | ✗ | ✓ | ✓ |
| 기술 활용 설명서 | `PROJECT_TECH_NOTE` | ✗ | ✓ | ✓ |
| 제출 서류 | `PROJECT_DOCUMENT_ITEM` | ✗ | ✓ | ✓ |
| 증빙 파일 | `DOCUMENTS` | ✗ | ✓ | ✓ |

즉 프로필에서 추가한 프로젝트는 **면접관에게 거의 빈 칸으로 보이고, 프로필에서는 채울 방법이 없었다.**
로드맵 PROJECT 단계를 완료해야만 채워졌다.

`/profile/projects/edit`을 만들어 로드맵 제출이 쓰는 `ProjectSubmissionService`와 `RoadmapSubmissionForm`을
**그대로 재사용**했다. 입력칸도 같은 파일(`common/project-submit-fields.jsp`)이라 두 화면이 받는 항목이
앞으로도 갈라지지 않는다.

다른 점은 **하나뿐**이다 — README·실행 화면 캡처를 필수로 받지 않는다(`validate(..., requireDocs=false)`).
로드맵에서는 그 서류가 "단계를 끝냈다"는 증빙이지만, 프로필은 예전에 한 프로젝트를 적어 두는 자리다.
서류가 없다고 막으면 아무것도 못 적는다. 목록의 간단 추가 칸은 그대로 뒀다 — 짧게 적고 넘어가는 길을
막지 않으려고.

## 7. 어드민 4종 (`51cb344`, `00eaf3b`, `84358d9`)

### 7-1. 감사 로그 (`/admin/audit`)

`ADMIN_AUDIT_LOG` 신설(`sql/29`). 관리자가 무엇을 바꿨는지 12종 액션으로 남긴다.

`admin_user_id`에 **`ON DELETE SET NULL`을 의도적으로** 걸었다. 프로젝트 규칙은 RESTRICT인데, 감사 로그는
관리자 계정이 지워져도 **기록 자체는 남아야** 의미가 있다. 그래서 `admin_login_id VARCHAR(50) NOT NULL`을
따로 둬서 누구였는지는 보존한다.

### 7-2. 면접관에게 활동 내역 (`scope_activity`)

깃허브 잔디처럼 날짜별 활동량(26주) + 최근 활동 타임라인. `SHARE_LINK.scope_activity` 추가(`sql/30`).

**기본 비공개로 따로 뗀 이유**: 며칠 몇 시에 무엇을 했는지까지 드러난다. 기본 이력에 묶으면 지원자가
통제권을 잃는다(NFR-4 본인 선택 공유, `scope_age`와 같은 판단).

### 7-3. 기능 설계서 · 기능별 테스트 목록 (`/admin/design`, `/admin/tests`)

손으로 쓰지 않는다. **빌드가 소스를 훑어** `src/main/resources/feature-coverage.json`을 만들고 화면은 그
리소스만 읽는다. 배포된 WAR에는 `src`·`docs`가 없어 실행 중에 소스를 읽을 수 없고, 손으로 쓴 문서는
코드보다 금방 낡는다. 골든 파일이 낡으면 테스트가 실패한다.

이 화면이 FR-114·115가 비어 있다는 걸 알려줬고, 그래서 5절을 하게 됐다.

## 9. 입력 실수에 에러 페이지가 뜨던 문제 (`09fdc85`, `3855534`)

보유 기술 스택에 이미 있는 기술을 넣으면 **409 에러 페이지**가 떴다. `resp.sendError(SC_CONFLICT)`를
쓰고 있었는데, `web.xml`에는 403·413·404·500만 매핑돼 있어 409·400은 톰캣 기본 화면으로 떨어진다.
적던 내용이 통째로 사라졌다.

`ProfileNotice`(세션 플래시) + `/profile` 리다이렉트로 바꿨다. 기술·스펙에 먼저 적용했고, 이번에
**프로젝트 칸에도 같은 문제가 남아 있어** 같이 맞췄다(날짜·팀 인원 형식 오류, 링크 형식 오류, 제목 누락).

관련해서 관리자 계정이 `/admin`에서 **무한 리다이렉트**되던 것도 고쳤다(`7b3067d`).
두 분기가 경로 판정 기준을 다르게 썼다 — `path.startsWith("/admin/")`만 봐서 `/admin` 자체가 빠졌고,
그 화면에서 다시 자기 자신으로 보냈다. `isAdminPath()` 하나로 통일하고, 테스트가 그 루프를 잡는지
버그를 되돌려 확인했다(3개 실패 확인).

임베디드 톰캣으로 화면을 실제로 띄워 보려 했는데 **하지 않기로 했다.** 두 가지 이유다.

1. 웹앱을 올리면 `@WebListener` 6개가 시작된다 — 전체 사용자 점수 스냅샷, 트렌드 수집, 탈퇴 정리,
   Work24 수집, 알림 catch-up, 시뮬레이션 정리. **공유 팀 DB와 외부 API를 건드린다.** 팀원 데이터를
   바꿀 수 없다.
2. 리스너를 피하는 방법(`Tomcat.addContext`)은 `tomcat-embed-core`가 필요한데, 그게 `jakarta.servlet`
   6.1을 번들로 들고 와서 지금 쓰는 6.0과 테스트 클래스패스에서 겹친다. 한 화면 렌더 확인을 위해
   872개 테스트 전체를 흔들 위험을 감수할 일은 아니다.

JSP 선컴파일이 EL 문법·태그 속성·taglib URI는 전부 잡는다. 남는 사각지대는 **런타임 값**이다
(`${x.noSuchProp}`는 `RecordElCoverageTest`가 본다). 리스너를 끌 수 있는 스위치를 두면 렌더 테스트도
안전해지는데, 그건 별 작업으로 남긴다.
