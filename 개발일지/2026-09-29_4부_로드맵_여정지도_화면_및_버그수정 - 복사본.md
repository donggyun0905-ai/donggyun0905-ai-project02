# 로드맵 "여정 지도" 화면 구현 및 화면 전역 버그 두 건

날짜: 2026-09-29
범위: FR-32·33·36 화면(JSP) 반영 — 화면설계 PDF의 로드맵 화면 그래픽 재현 + 그 과정에서 발견한 버그 수정

## 1. 개요

화면설계 PDF(`개발자료/화면 설계/스펙_오디세이_화면설계.pdf`)를 다시 렌더링해 로드맵 화면("5. 내 로드맵")을 확인해보니, 지금까지 단순 리스트로만 구현했던 부분이 실제로는 **좌우로 교차 배치된 카드 + 굽이치는 길 그래픽 + 원형 상태 마커("완료"/"지금 할 일"/"남음"/"잠김")**로 된 "여정 지도"였다. 이걸 재현하는 과정에서 로드맵 화면 자체의 버그 하나와, **모든 화면에 걸친** 버그 하나를 같이 잡았다.

## 2. 버그: 로드맵 화면 500 에러 — EL 예약어 충돌

- **문제**: 로드맵 화면을 열면 계속 `error.jsp`(500)로 떨어졌다. `RoadmapService`를 직접 실행하는 진단 코드로는 재현이 전혀 안 됐다(예외 없이 정상 동작) — 이상하다 싶었는데, 사용자가 받아온 실제 Tomcat 스택트레이스를 보니 `org.apache.jasper.compiler.Validator`에서 나는 에러였다. 즉 JSP **실행 중** 에러가 아니라 **컴파일 자체가 실패**하는 것이었다.
- **원인**: `TierProgress.isEmpty()` — `empty`는 EL(JSP 표현언어)의 **예약어**다(`${empty someList}`처럼 빈 값 판정 연산자로 쓰인다). `${t.empty}`처럼 프로퍼티로 접근하면 Jasper가 태그 검증 단계에서 파싱에 실패해 JSP 컴파일 자체가 깨진다. 순수 Java 로직 테스트나 직접 실행으로는 절대 못 잡는, JSP 컴파일 단계에서만 터지는 버그였다.
- **어떻게 고쳤나**: `isEmpty()` → `isEmptyTier()`로 개명(`RoadmapService.java`), `roadmap.jsp`의 `t.empty` 참조 2곳을 `t.emptyTier`로 수정, 관련 테스트도 같이 수정.

## 3. 버그: 모든 화면 본문이 왼쪽으로 치우쳐 보임

- **문제**: 로드맵 화면 크기를 키우다가 발견 — 로드맵뿐 아니라 **전체 화면**에서 본문(`main`)이 화면 가운데가 아니라 살짝 왼쪽으로 밀려 보였다.
- **원인**: `footer.jsp`에 `<aside id="trend-sidebar">`라는, 설계상 항상 비어있게 둔 자리가 있었다(각 화면이 트렌드 위젯을 본문 오른쪽 칼럼에 직접 넣는 방식으로 대체됐기 때문). CSS에도 `#trend-sidebar:empty { display:none; }`로 "비어있으면 숨긴다"는 규칙이 이미 있었는데, `<aside>` 태그 사이에 JSP 주석 앞뒤로 남아있던 **줄바꿈/들여쓰기 공백**이 주석 제거 후에도 남아서 `:empty` 판정에 실패하고 있었다(공백도 자식 텍스트 노드로 쳐서 "완전히 비어있음"이 성립 안 함 — CSS `:empty`의 잘 알려진 함정). 그 결과 `width:260px`가 모든 화면에서 항상 적용돼 본문이 그만큼 밀려 보였다.
- **어떻게 고쳤나**: `<aside id="trend-sidebar"></aside>`를 태그 사이 공백 없이 한 줄로 붙여써서 실제로 빈 엘리먼트가 되게 고쳤다. 재발 방지용으로 주석을 남겨둠.

## 4. "여정 지도" 그래픽 구현과 여러 차례 반복

JS 금지가 실제 팀 규칙은 아니었다(`CLAUDE.md`는 "프론트엔드 프레임워크 미사용"만 명시) — 다만 이번에도 순수 HTML 표준 기능(`<details>/<summary>`)만으로 충분해서 JS는 쓰지 않았다. 사용자 피드백을 받으며 여러 차례 구조를 바꿨다:

1. **1차**: ENTRY~EXPERT 전체 티어를 배지 + 좌우 교차 카드로 한 화면에 표시(화면설계 PDF와 동일한 구조). 가운데 축은 `border-left` 직선.
2. **직선 → 물결**: "그냥 직선인데?" 피드백 → 가운데 축을 물결 모양 SVG를 세로로 타일링한 배경으로 교체. 카드 배치와 픽셀 단위로 맞물리진 않지만(그러려면 JS로 카드 높이를 재야 함), 시각적으로 굽이치는 느낌은 남도록 함. 동시에 전체 폭을 넓히고(`mainWide`, 860px→1140px) 마커·카드 크기도 확대.
3. **구조 단순화**: "이후에 있을 길은 없어도 되는데 이전에 한 길을 돌아보는건 있어야" → 잠긴 미래 티어(카드·배지)를 화면에서 아예 제거하고, 완료한 단계는 `<details>`로 접어서 "지나온 길 돌아보기"로 분리.
4. **접이식 → 스크롤**: "위로 드래그는 넣어달라고, 이미 한 건 볼 수 있게, 색은 뿌옇게" → 클릭해서 펼치는 `<details>` 대신 그냥 스크롤하면 보이는 평범한 섹션으로 되돌리고, 완료한 카드는 `opacity` + `grayscale`로 색을 옅게(뿌옇게) 처리.
5. **컨테이너 하나로**: "박스를 새로 만드는 게 아니라 컨테이너 하나에" → "지나온 길"과 "지금 할 일"로 나뉘어 있던 카드 두 개를 스크롤 트랙 하나로 합쳤다. 완료한 단계(흐리게)가 위쪽에, 지금 열린 티어의 미완료 단계(선명하게)가 아래쪽에 순서대로 이어진다.
6. **스크롤 컨테이너 분리**: "네모 칸 박스가 컨테이너로 치면 거기서 드래그 되게" → 그 박스 자체를 `max-height` + `overflow-y:auto`인 별도 스크롤 컨테이너로 만들어서, 페이지 전체가 아니라 박스 안에서만 드래그/스크롤되게 함.
7. **마무리**: 스크롤바 기본 회색을 골드/탄 팔레트로 테마 적용(`scrollbar-color` + `::-webkit-scrollbar`), 박스 높이를 고정값(480px) 대신 뷰포트 기준(75vh)으로 바꿔 화면 클수록 넉넉해지게 함.

## 6. 남은 것 / 참고

- 실제 브라우저 렌더링을 Claude가 직접 확인할 방법이 없어서, 이번 라운드 전부 "정적 검증(태그 중첩 프로그램 검증, EL 문법 확인) + 사용자 실제 확인 → 피드백" 왕복으로 진행했다. `Validator`/EL 관련 버그는 이런 왕복이 아니면 사전에 못 잡는 종류라는 걸 배웠다.
- 스킬 시멘틱(임베딩) 매칭은 여전히 미착수 — TD-1 범위인데 로드맵 담당 스코프인지 팀 확인 필요.
