# 팀 브랜치 통합(직무 발굴·트렌드 기술) 및 프로필 희망 직무 검색 개선

날짜: 2026-09-29
범위: FR-21·22(프로필 기본정보), FR-34·38·39(직무 발굴), FR-54·55(트렌드 기술) — 다른 담당자 브랜치를 내 브랜치로 가져와 통합

## 1. 개요

팀원들이 각자 브랜치에서 작업 중인 기능 중 이미 완성된 두 가지(직무 발굴 — kangdain, 트렌드 기술 사이드바 — seongwon)를 내 브랜치로 가져와 로드맵과 실제로 이어지게 통합했다. 동시에 로드맵 화면에서 발견된 프로필 관련 버그 두 개(희망 직무 저장 안 됨, 사이드 메뉴 클릭 안 됨)를 고쳤다.

## 2. 프로필 희망 직무 — 드롭다운에서 검색창으로

- **배경**: 실제 채용공고 데이터를 보니 사용자가 직무명을 다르게 알고 있는 경우(예: "데이터 엔지니어"를 "데이터 프로그래머"로 인지)가 흔해서, 드롭다운(`<select>`)만으로는 원하는 직무를 못 찾을 수 있다는 문제 제기가 있었다.
- **구현**: `<input list="jobOptions"> + <datalist>`(HTML5 표준, JS 불필요)로 검색창을 만들고, 전체 직무명 + `JOB_ALIAS`(별칭) 전체를 후보로 넣었다. 서버(`ProfileService.resolveJobQuery`)에서 정식 명칭 → 별칭 → 편집 거리(레벤슈타인) 기반 근접 매칭 순으로 해석한다.
- **안전장치**: 편집 거리로 골라낸 애매한 매칭은 바로 저장하지 않고 "OOO 맞나요?" 확인 화면을 먼저 보여주고 동의해야 저장한다 — 희망 직무는 격차분석·로드맵을 좌우하는 값이라 잘못 자동교정되면 위험하기 때문. 확인 화면에는 직무 카테고리와 등록된 별칭 목록을 "무슨 일을 하는 직무인지" 힌트로 같이 보여준다(JOB에 설명 컬럼이 없어서 대안으로 사용).

### 버그: 검색창에 입력만 하고 저장이 안 되던 문제

- **문제**: 원래 희망 직무는 검색창 + 별도 라디오 버튼("아직 모르겠음"/"선택함") 조합이었는데, 검색창에 입력만 하고 라디오를 안 누르면 서버가 `desiredJobStatus != "SET"`로 보고 조용히 `desiredJobId`를 저장하지 않았다. 에러 메시지도 없어서 사용자 입장에선 그냥 "저장이 안 되는" 것처럼 보였다.
- **어떻게 고쳤나**: 라디오 버튼을 아예 없애고, 검색창에 값이 있으면 자동으로 "선택함", 비어 있으면 "아직 모르겠음"으로 서버에서 판단하도록 바꿨다.

## 3. kangdain 브랜치 — 직무 발굴(설문 → 추천 → 선택) 가져옴

- `JobDiscoveryService`(설문 응답 + 보유 스펙으로 추천 3~5개 산출), `SkillMatcher`/`ExactMatcher`(스킬명 매칭, 추후 임베딩 매처로 교체 가능한 구조), `JobDiscoveryScorer`를 그대로 가져왔다.
- 후보 선택 시 `/gap-analysis?jobId=...`로 이동하는데, 이게 어제 만든 `GapAnalysisServlet`의 `jobId` 파라미터 처리와 그대로 맞물려서 수정 없이 바로 연동됐다.
- **보완**: `selectRecommendation()`이 후보를 선택 상태로만 바꾸고 희망 직무(`desired_job_id`)는 안 건드리고 있었다. 그대로 두면 직무 발굴만 거치고 로드맵을 만든 사용자가, 프로필에서 따로 "선택함"을 안 눌렀다는 이유로(아래 4번 항목의) 로드맵 안내 카드에 막혀버리는 모순이 생긴다. 후보 선택 = 희망 직무 확정으로 보도록 고쳤다.

## 4. 로드맵 — 희망 직무 없으면 안내 카드로 대체

로드맵은 목표 직무가 있어야 의미가 있어서, `RoadmapServlet`에서 `desired_job_id`가 없으면 로드맵 내용 대신 "희망 직무를 먼저 정해주세요" 안내 카드(직무 찾기/프로필 링크)를 보여주도록 했다.

## 5. seongwon 브랜치 — 트렌드 기술 사이드바 가져옴

- `TrendCollectService`가 매일 0시(+ 서버 기동 시 오늘 수집분이 없으면 즉시) Hacker News·GitHub·dev.to·Lobsters·GeekNews에서 글을 모아 Groq LLM(`TrendLlmService`)으로 기술명·설명·관련 직무·확신도를 정리하고, 확신도를 통과한 것만 저장한다.
- `TrendWidgetFilter`가 원래 9개 화면에만 적용돼 있었는데, 로드맵 화면에도 필요해서 `/roadmap`을 대상에 추가했다.
- **설정 방식 혼선**: seongwon이 만든 `AppConfig`는 `config.properties`(프로젝트 루트, 별도 파일)를 읽는 방식이었는데, 팀에서 API 키·DB 설정은 `.env`로 통일하기로 확정했다는 걸 뒤늦게 확인해서 `main` 브랜치에 있던 `.env` 기반 `AppConfig`로 교체했다(`get(key)` 시그니처는 같아서 호출부 코드 변경은 불필요).

## 6. main 브랜치 동기화

로드맵·격차분석·프로필 완성분을 main에 반영하면서, main이 이미 kangdain·seongwon의 PR을 병합해둔 상태(단, seongwon의 PR은 트렌드 수집 로직이 실제로 만들어지기 *전* 스냅샷이 병합된 상태였음)라는 걸 확인했다. 병합 과정에서 발견한 진짜 회귀 버그도 하나 있었다:

- **문제**: `ExactMatcher.java`가 kangdain의 최종 리팩터링(매칭 실패 시 `null` 대신 `MatchResult.none()` 반환) 이전 버전으로 main에 남아 있었다. 아마 kangdain 쪽 브랜치 병합 시 충돌 해소가 잘못돼서 옛날 버전이 살아남은 것으로 보인다.
- **어떻게 고쳤나**: 최신 버전으로 교체하고, 그 구버전 계약을 테스트하던 `ExactMatcherTest` 2개(`unknownSkill_returnsNull`, `nullOrBlank_returnsNull`)를 새 계약(`MatchResult.none()`, `skillId()`가 null)에 맞게 수정했다.

## 8. 참고 — 사이드 메뉴 드로어 클릭 안 되던 버그(745923e)

`.nav-drawer-panel`에 `position`이 없어서(static), 배경 닫기용 `<label>`(같은 부모의 형제 요소, `position:absolute`)이 DOM 순서와 무관하게 항상 위에 그려져 패널 안 모든 메뉴 링크 클릭을 가로채고 있었다. `.nav-drawer-panel`에 `position: relative`만 추가해 같은 포지션드 레이어로 올리니 DOM 순서(label 다음)대로 패널이 위에 그려지고 정상 클릭됐다.
