# 프로필 기술·스펙 입력 검사 — 엉터리 글자 차단과 시맨틱 이름 제안

날짜: 2026-10-06
관련 커밋: 이 일지와 함께 올린 커밋 1개
푸시: `origin/donggyun0905`, `origin/main` (사용자 요청으로 둘 다)

## 1. 개요

main 최신 상태(PR #18까지)를 브랜치로 받은 뒤 작업했다. 받는 것은 빨리감기로 끝났고, 전체 테스트 729개가 통과했다.

**요청**: 프로필에서 기술이나 스펙을 추가할 때 `sdafdsafdsa` 같은 이상한 글이 그대로 저장된다.
이미 있는 시맨틱(임베딩) 매칭을 이용해 이를 알아보고 글을 고쳐 주는 기능을 만든다.

## 2. 동작

입력칸을 벗어나거나 잠시 멈추면 서버에 물어보고, 칸 바로 아래에 결과를 띄운다.
기술 추가·수정 칸과 스펙 추가·수정 칸 모두에 붙어 있다.

| 입력 예 | 결과 |
| --- | --- |
| `sdafdsafdsa`, `ㅁㄴㅇㄹ`, `qwerty`, `1234` | "의미 없는 글자처럼 보여요" — **저장 막힘** |
| `Pyhton`, `Reakt`, `Kubernetis` | "혹시 이 기술인가요?" + 이름 버튼(누르면 칸의 값이 바뀜) |
| `자바`, `스프링부트` | "'Java'(으)로 인식했어요" |
| `머신러닝 파이프라인` | "목록에 없는 기술이에요" — 저장은 가능(새 기술일 수 있음) |
| 자격증 `정처기`, `컴활`, `빅분기`, `토익 850` | 정식 이름 제안 → 로드맵 자격증 단계와 이어진다 |
| 자격증 `정보처리기싸`, `리눅스마스터` | 후보 여러 개(정보처리기사·기능사 / 1급·2급) |
| 어학 `토익 850`, `OPIc IH` | 점수·등급을 떼고 시험 이름만 보고 인식. 목록에 없는 어학 시험(JLPT 등)은 안내하지 않음 |
| 수상 | 엉터리 글자만 막는다 |

화면 검사를 거치지 않은 직접 요청도 엉터리 이름이면 서버가 400으로 거절한다.

## 3. 판단 방식

**엉터리 판단은 규칙으로 한다** (`util/GibberishDetector`)
- 처음에는 임베딩으로 가리려 했다. 그런데 실측해 보니 엉터리 입력도 가장 가까운 스킬과 0.58~0.61이 나왔다
  (`sdafdsafdsa`→Kafka 0.61). 임베딩으로는 "말이 되는 글자인가"를 가를 수 없었다.
- 규칙: 홑자모(ㅁㄴㅇ), 글자 없음(1234), 같은 글자 4번 연속, 키보드 한 줄(qwerty), 몇 글자 반복(asdasd), 모음 없음 / 자음 5개 연속.
- 영어 규칙은 5글자 이상 단어에만 적용한다. 대문자 약어(MSSQL·HTTPS)는 예외이고, `LightGBM`처럼 대소문자가 섞인 이름은 경계에서 나눠 본다.

**고칠 이름 찾기는 기존 매칭과 시맨틱을 같이 쓴다** (`service/ProfileInputChecker`)
1. SKILL·SKILL_ALIAS·CERTIFICATION 이름과 같으면(대소문자·공백 무시) 통과
2. 엉터리면 차단
3. 기존 `EmbeddingMatcher`(이름·별칭·오타·임베딩)가 찾으면 그것만 제안. 후보를 더 붙이면 "Java 17"에 JavaScript까지 나왔다.
4. 못 찾으면 편집 거리(0.65 이상)와 임베딩 유사도 중 높은 쪽으로 후보를 최대 3개 고른다.
   - 기술: 0.70 이상 — `Pyhton`→Python 0.82, `Reakt`→React 0.74. `웹 개발`→Webpack(0.69)은 걸러진다.
   - 자격증: 0.75 이상 — 이름이 길어 점수가 높게 나온다.
5. 자격증 줄임말(정처기·컴활·빅분기·토익·오픽 등)은 임베딩이 못 잡아서 작은 표로 둔다.

모델이 없는 PC에서는 4)의 임베딩 후보만 빠지고 나머지는 그대로 동작한다.

## 4. 이 PC의 임베딩 모델 로딩 실패 — 원인과 조치

- 이 PC에는 모델이 없어 `C:/models/ko-sroberta-multitask`에 받았다(440MB, 저장소 밖).
- 기본 JDK(`D:\Java\jdk-17`, Oracle 17.0.12)로는 `UnsatisfiedLinkError: DLL 초기화 루틴을 실행할 수 없습니다`가 난다.
  JDK bin에 든 msvcp140·vcruntime140이 14.36인데, ONNX Runtime 1.21(DJL 0.38)은 14.40 이상이 필요하다.
  JDK 복사본에서 이 DLL 3개만 Windows 최신 것(14.51)으로 바꾸면 정상 동작하는 것을 확인했다.
  코드에서 System32 DLL을 미리 올리는 방법은 효과가 없어서 되돌렸다.
- **같이 고친 버그**: 이 오류는 `Exception`이 아니라 `Error`라서 `EmbeddingMatcher.embedder()`의 catch를 빠져나간다.
  모델 경로를 설정한 PC에서 JDK가 오래됐으면 스킬 매칭을 쓰는 화면이 500으로 멈출 수 있었다.
  `LinkageError`도 잡아서 "모델 없음"처럼 건너뛰게 했다.
- `.env`에는 모델 경로를 넣지 않았다. 확인할 때는 8090 테스트 서버에만 환경변수로 줬다.

## 5. 검증

- 새 테스트 2개를 작성했다.
  - `GibberishDetectorTest` 37건: 엉터리 12, 정상 이름 23(LightGBM·PyTorch·MSSQL·자바 백엔드·교내 해커톤 대상 등), 빈 입력
  - `ProfileInputCheckerTest` 11건: 공유 DB 시드를 읽기만 한다. **DB에 있는 모든 스킬·별칭·자격증 이름이 하나도 거절되지 않음**을 포함한다.
  - 모델이 없을 때와 있을 때(JDK 복사본) 둘 다 통과했다.
- 8090 테스트 서버에 올려 화면을 캡처하며 확인했다.
  - 엉터리, 오타 제안, 별칭 인식, 목록에 없음, 자격증 줄임말, 자격증 오타, 수정 칸 안내
  - 제안 버튼을 누르면 값이 바뀌고 다시 검사된다.
  - 엉터리를 저장하려 하면 페이지가 넘어가지 않는다.
  - 직접 POST하면 기술·스펙 모두 400이 난다.
  - 테스트 계정은 논리 삭제로 정리했다.
- 전체 `mvnw test` 777개 통과(실패 0, 건너뜀 8).
