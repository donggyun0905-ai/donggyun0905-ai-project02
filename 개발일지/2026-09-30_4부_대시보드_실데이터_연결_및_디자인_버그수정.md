# 대시보드 실데이터 연결 · 디자인 모션 · 버그 수정 3건

날짜: 2026-09-30
관련 요구사항: FR-41~44(대시보드)

## 1. 개요

로드맵 쪽 큰 작업이 끝난 뒤, 그동안 고정 예시 데이터로만 만들어져 있던 대시보드를 실제 서비스에 연결하고, 디자인 다듬기(호버·클릭 모션) 요청을 처리했다. 마지막에는 실사용 중 발견된 버그 세 개를 바로잡았다.

## 2. 대시보드 — 고정 예시값을 실제 데이터로 연결

`DashboardServlet`이 "화면만 먼저 만든다"는 팀 지시로 전부 하드코딩된 예시 데이터였던 걸, 이미 만들어진 서비스들(로드맵·점수·미션·격차분석·D-day)을 읽기 전용으로 모아 실제 데이터로 교체했다.

- 여정 지도 + "지금 할 일": `RoadmapService.computeProgress`/`getSteps` 재사용.
- 헤더 문구(목표 직무·현재 단계): `UserDto.desiredJobId` + 로드맵 진행도.
- 나의 등급: `ScoreService` + `LEVEL_TIER` 조회. 다음 등급까지 남은 점수·진행률 계산은 서블릿에서 미리 해서 JSP는 출력만 하게 함(claude.md: JSP에 계산 금지).
- 오늘의 미션: `DailyMissionService.getOrAssignToday` 재사용(3부에서 가져온 seongwon 기능).
- 다가오는 일정: `DdayAlertDao` 조회, 지난 일정 제외 가까운 순 3개.
- 부족한 필수 역량: `GapAnalysisService` 최근 분석의 MISSING 항목.
- "스펙 완성도"(종합 점수)는 실제로 계산하는 배치/서비스가 당시 아무도 없어서, 없는 공식을 지어내지 않고 자격증·프로젝트·보유기술 개수만 사실대로 보여주는 선에서 마무리(이후 집에서 작업한 `SpecScoreService`로 실제 연결됨 — 별도 기록).

## 3. 디자인 — 전 화면 공용 호버·클릭 모션

`style.css`에 트랜지션이 하나도 없어서 버튼·카드·메뉴 호버/클릭이 전부 즉시 전환되던 걸 다듬어달라는 요청.

- 버튼: 호버 시 살짝 떠오름(그림자 생김), 클릭 순간 눌리는 느낌.
- 카드/여정 카드: 호버 시 그림자 깊어짐 + 살짝 떠오름(완료·잠긴 카드는 제외).
- 여정 마커: 호버 시 살짝 확대.
- 목록 항목·드로어 메뉴: 호버 시 테두리 강조/밀림.
- `prefers-reduced-motion`(모션 줄이기 설정)이면 트랜지션 자체를 안 걸도록 미디어 쿼리로 처리.

## 4. 버그 수정 3건

### 로그인 성공 후 메인 화면 변경

로그인하면 `/dashboard`로 보내던 걸 `/roadmap`으로 변경 — 사용자가 메인 화면을 로드맵으로 바꿔달라고 요청.

### 대시보드 여정 지도 연결선 사라짐

- **문제**: 대시보드를 실제 데이터로 바꾸면서(`c:forEach`) 티어 칩 사이를 잇던 연결선이 안 보임.
- **원인**: 고정 예시 데이터 버전에는 칩 4개 사이에 수동으로 넣어둔 연결선 `<div>` 4개가 있었는데, `c:forEach`로 갈아끼우면서 그 연결선 자체를 빠뜨림.
- **수정**: `varStatus`로 마지막 티어가 아닐 때만 연결선을 그리도록 추가, 완료된 티어 뒤는 teal색·아니면 회색.

### 로고 클릭 시 에러 화면 뜨던 문제

- **문제**: 헤더의 로고/브랜드 이름(`href="${ctx}/"`)을 누르면 404 에러 화면(`error.jsp`)이 떴다.
- **원인**: `index.jsp`의 `<c:redirect url="${pageContext.request.contextPath}/login" />`에서, JSTL의 `c:redirect`는 "/"로 시작하는 `url`을 이미 컨텍스트 루트 기준으로 해석하는데 여기에 `contextPath`를 또 붙여서 `/스펙오디세이/스펙오디세이/login`처럼 컨텍스트 경로가 두 번 붙은 잘못된 URL로 리다이렉트되고 있었다.
- **수정**: `<c:redirect url="/login" />`로 변경.
