## 2. 화면 다듬기 (`0b104e0`, `26f00ad`)

- **이모지 제거**: 메뉴·제목·상태 표시·로드맵 마커의 이모지를 SVG 선 아이콘(`css/icons.css`)으로 바꿨다. CSS mask 방식이라
  글자색을 그대로 따른다. 로드맵 단계 설명에 저장되던 이모지 앞머리도 뺐고(아이디어는 `아이디어: `), 이미 저장된 값은
  `sql/22`로 바꿨다(공유 DB 적용 완료).
- **회원가입**: 개인정보 동의는 가입하기를 누르면 뜨는 작은 창에서 받는다(필수 항목을 다 체크해야 버튼이 눌리고, 서버 검증은 그대로).
  이어서 기본 정보 → 추가 정보 → 동의의 3단계로 나눴다. 화살표를 누르면 상자가 옆으로 넘어가고, 마지막 단계에서만 가입하기 버튼이
  나온다. 비밀번호 확인 칸을 추가했다(서버에서도 확인).
- **입력칸·파일 버튼**: url·number 칸을 다른 칸과 같은 모양으로 맞추고 링크 칸에 링크 아이콘을 넣었다. 파일 선택은 점선 상자,
  내려받기 링크는 칩 모양(`file-link`)으로 통일했다.
- **화면 점검에서 고친 것**: 대시보드 '격차 분석 보기' 버튼 글자 꺾임, 분석일 `2026-10-03T22:05:20` → `2026-10-03 22:05`,
  프로필의 영어 코드(LANGUAGE·INTERMEDIATE)를 한글로, 면접관 계정 상단의 점수 배지 제거, 랜딩의 예전 등급 이름을 지금 이름으로.

## 3. 공통 자격증(어학·컴활) 로드맵 노출 (`811f1ed`)

**문제**: 로드맵은 직무 자격증을 하나만 넣고, 그게 다 떨어져야 공통 자격증이 나왔다. 그래서 컴활은 사실상 보이지 않았고,
어학 자격증은 DB에 아예 없었다.

**수정**: 입문 티어에 직무 자격증과 별도로 공통 자격증 한 칸을 넣는다. 프로필 어학 항목에 이미 있으면("토익 850" 같은 한글 표기 포함)
건너뛴다. `sql/23_seed_certification_common.sql`로 TOEIC·TOEIC Speaking·OPIc(공통)과 웹디자인개발기능사를 추가했다.
웹디자인개발기능사는 프론트엔드 계열 자격증이 0개여서 넣었다.

## 4. 트렌드 위젯 — 희망 직무에 맞는 트렌드만 (`13ae039`, `a1136cc`, `52d55b6`)

- 직무 찾기에서 추천 직무를 골라도 세션의 사용자 정보가 그대로라 다시 로그인하기 전까지 희망 직무가 비어 있었다. 선택 직후
  세션을 새로 읽어 맞췄다(`13ae039`).
- 위젯은 이제 매 요청 DB에서 희망 직무를 읽는다. 순서는 내 직무 → 같은 직무 계열 → 그래도 없으면 '아직 없음'이다.
  엉뚱한 최근 트렌드는 보여주지 않고, 희망 직무가 없을 때만 최근 트렌드를 보여준다.
- 관련도 기준은 0.8에서 0.85로 올렸다. 오늘 수집분에 "프론트엔드 개발자 ↔ C++·Python"(0.80) 같은 억지 연결이 있었기 때문이다.
- 18개 직무를 전부 화면에서 확인했다. 기획(PM) 계열 3개는 수집된 트렌드가 없어 안내 문구만 나온다(→ 5절 4번).

## 5. 설문 변경 안내 (`f2e99b2`)

설문을 한 번이라도 한 사람에게 아직 답하지 않은 문항이 있으면 대시보드와 직무 찾기에서 다시 풀어 보라고 안내하고,
새 문항에 표시를 붙인다. 앞으로 문항이 바뀔 때도 그대로 동작한다. 기존 응답자 9명의 새 6문항 임시 3점은 논리 삭제해서
이 안내를 받게 했다. 추천 점수는 계열 평균이라 그대로 계산된다. 대시보드 여정 지도의 티어 표시는 원형으로 키우고,
잠긴 티어는 자물쇠로 표시한다.

## 6. 왼쪽 "한눈에 보기" 위젯 (`52d55b6`)

서류 보관함 아래가 비어 보여 세 가지를 한 상자에 모았다(`GlanceService`).
- 다가오는 D-day 3개
- 로드맵의 지금 할 일(자격증·기술은 이름으로)
- 다음 등급까지 남은 점수

JSP가 읽는 record에는 팀 규칙대로 `getX()`를 둔다. Tomcat 10.1 EL은 record 접근자를 못 읽어서, 처음에는 모든 화면이 500이 났다.
테스트(`GlanceServiceTest`)도 같이 넣었다. 대시보드 "지금 할 일"에 AI 프로젝트 아이디어 설명이 통째로 찍히던 것도 제목만 보이게 고쳤다.

## 7. README · ERD · DAO 가이드 동기화 (이 커밋)

- **README**:
  - 기능 목록에 3단계 가입, 탈퇴 30일 유예, 좌우 위젯, 아이콘을 반영했다.
  - SQL 목록과 새 DB 실행 순서를 지금 파일 기준으로 고쳤다. 새 DB에도 `19_seed_skill_alias_more`·`23`이 필요하다.
  - 기존 DB에 덧붙일 20~23을 안내하고, "21 적용 뒤 18 실행 금지" 경고를 넣었다.
  - 검증: 공유 서버에 임시 DB를 만들고 README 순서대로 실행해 확인했다. 운영 DB와 컬럼 489개가 같고, 설문 18·직무 18·스킬 163·
    자격증 41·티어 5개였다. 확인 뒤 임시 DB는 지웠다.
- **ERD HTML** (`docs/spec-odyssey-erd.html`):
  - 실제 DB와 비교해 빠진 테이블 `SCORING_RULE`, `TECH_ARTICLE_ATTACHMENT`와 관계 1개를 추가했다.
  - 컬럼 `USERS.withdraw_requested_at`, `TECH_ARTICLE_COMMENT.reply_to_user_id`를 추가하고 `user_type` 길이를 VARCHAR(15)로 고쳤다.
  - 결과는 49개 테이블 · 관계 69쌍이고, 비교 스크립트상 차이는 없다.
- **DAO 가이드 HTML** (`docs/spec-odyssey-dao-guide.html`):
  - 코드에서 메서드 시그니처·반환형·트랜잭션 여부·사용처를 다시 뽑았다(DAO 48 · DTO 49 · 메서드 234 · 테스트 파일 113).
  - 새 DAO 5개(ScoringRule, TechArticle·Comment·Attachment·Reaction)에 설명을 채우고, '스펙 아카이브' 도메인을 추가했다.
  - 화면 캡처로 렌더링을 확인했고 JS 오류는 없다.
- `UserDao`: 엉뚱한 메서드 위에 붙어 있던 `// FR-12 …` 주석을 제자리(`updateLastLogin`)로 옮겼다(주석만 변경).
- 검증: 전체 `mvnw test` 590개 통과(실패 0, 건너뜀 3).
