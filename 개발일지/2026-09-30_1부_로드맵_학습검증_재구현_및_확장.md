# 로드맵 SKILL/CERT 학습 검증 재구현 및 확장

날짜: 2026-09-30
관련 요구사항: FR-32·33·36

## 1. 개요

전날(09-29) 집에서 작업했던 두 가지(`CertificationDao` COMMON 카테고리 버그 수정, 로드맵 "다음 단계 미리보기" + LLM 프로젝트 아이디어 제안)가 집 PC에서 푸시가 안 된 채로 남아 커밋이 통째로 유실됐다는 걸 확인했다. 집에서 미리 써둔 개발일지(`2026-09-30_로드맵_개선_및_개발환경_정비.md`)를 스펙 삼아 처음부터 재구현했고, 그 과정에서 "SKILL 단계도 완료 체크 버튼 하나뿐"이라는 더 근본적인 문제를 발견해 ENTRY~EXPERT 전 티어, 그리고 뒤늦게 CERT까지 학습 검증 체계를 전부 새로 만들었다.

## 2. CertificationDao COMMON 카테고리 버그 재수정

- **문제**: `findByJobCategory`가 정확히 일치하는 카테고리만 조회해서, 컴활·정보처리기능사 같은 범용(COMMON) 자격증이 어떤 직무를 골라도 로드맵 후보에 안 떴다.
- **수정**: `WHERE (job_category = ? OR job_category = 'COMMON')` + 대상 카테고리를 COMMON보다 먼저 보여주는 정렬 추가.

## 3. 로드맵 "다음 단계 미리보기" + LLM 프로젝트 아이디어 재구현

- 잠긴 다음 티어 하나를 `opacity:0.65`로 흐리게 미리 보여주는 섹션을 `RoadmapService.getNextLockedTier()`(안 쓰이고 있던 메서드) 기반으로 재구현. 액션 버튼 없음 — 잠긴 단계는 완료 불가.
- `ProjectIdeaService` 신설: `TrendLlmService`의 Groq 호출 패턴(재시도·JSON 강제·실패 시 폴백)을 그대로 재사용해, 목표 직무+부족 기술로 구체적인 프로젝트 아이디어 1개를 생성. DB 트랜잭션을 열기 전에 미리 호출해서, 느려지거나 실패해도 커넥션을 물고 있지 않게 했다. 실패하면 기존 고정 문구로 조용히 대체(FR-111).

## 4. SKILL 단계 학습 검증(규칙 기반) 전 티어 확장

여기부터는 집 PC 작업 범위를 넘어선 것 — "SKILL 단계가 전부 완료 체크 버튼 하나뿐"이라는 걸 재구현 과정에서 다시 짚고 넘어가기로 했다. AI 채점안도 검토했으나 학생 프로젝트 규모에서는 비용·일관성 문제로 규칙 기반을 먼저 채택(4-1안, AI는 나중에).

- **ENTRY**: 공부노트 제출 → 300자 이상 + 기술명 2회 이상 + 코드 블록 1개 이상 자동 판정. `SkillProofGrader` 신설(순수 규칙 로직, 테스트 용이하게 분리).
- **CORE/ADVANCED**: 프로젝트 등록 또는 기존 프로젝트 업그레이드(`USER_PROJECTS.upgraded_from_project_id`) + 증빙 파일. 등록 자체를 증빙으로 신뢰.
- **EXPERT**: 기술 설명 글 제출 → 800자 이상 + 기술명 3회 이상 + 외부 링크 1개 이상.
- `ROADMAP_STEP`에 `proof_type`/`proof_content`/`evidence_project_id`/`review_status`/`review_note` 5개 컬럼 추가, 팀 공유 DB에 ALTER 적용.

### 수정: 텍스트 입력 → PDF 업로드로 되돌림

처음엔 공부노트·기술 설명 글을 순수 텍스트(`<textarea>`)로 받게 단순화했는데, db-design.md 원안(DOCUMENTS 파일 저장)과 다르다는 걸 사용자가 확인하고 PDF 업로드로 되돌리라고 지적. `PdfTextUtil`(PDFBox)로 업로드된 PDF에서 텍스트를 뽑아 그대로 규칙 판정에 쓰고, 원본 PDF는 통과 여부와 상관없이 `DOCUMENTS`(새 컬럼 `roadmap_step_id`로 연결)에 남겨 제출 이력 자체를 증빙으로 삼는다.

## 5. CORE/ADVANCED 구분 확정

- 처음엔 CORE/ADVANCED 둘 다 신규/업그레이드 자유 허용이었는데, "심화 단계는 반드시 발전시킨 흔적이 있어야 한다"는 취지로 **ADVANCED는 반드시 기존 프로젝트 업그레이드만 인정**(신규 불가)하도록 확정. 업그레이드할 프로젝트가 없으면 폼 자체를 숨기고 "CORE부터 먼저 하라"는 안내만 보여준다.

## 6. "로드맵이 한 번 만들면 고정되는 문제" 해결 — 요구 기술 변화 감지 배너

- 트렌드가 바뀔 때마다 관련 유저 전원의 로드맵을 자동 재생성하면 AI 비용이 유저 수 × 갱신 주기만큼 반복돼서 기각.
- 대신 `JOB.requirement_version` / `GAP_ANALYSIS.job_requirement_version` 스냅샷을 비교해 DB 조회만으로 변화를 감지(비용 0원)하고, 로드맵 화면에 배너로만 알린다. 사용자가 "재분석하고 반영" 버튼을 직접 눌러야만 실제 재분석(AI 비용 발생 지점)이 일어나는 구조로 분리.
- `JobDao.bumpRequirementVersion()`은 향후 워크넷 재수집 파이프라인이 호출할 진입점만 미리 만들어둠 — 아직 호출하는 곳 없음(2주차 이후 범위).

## 7. CERT 단계도 증빙 서류 첨부로 변경

재구현 작업 중 CERT 단계만 여전히 범용 "완료 체크" 버튼 하나로 남아있던 걸 뒤늦게 발견. `submitCertProof(userId, stepId, certificateFile)` 신설 — 합격 확인서·자격증 사진 등 서류 1개를 `DOCUMENTS`에 저장(`proof_type='CERT_DOCUMENT'`)하고 완료 처리. 별도 자동 판정 없이 첨부 자체를 신뢰(CORE/ADVANCED와 같은 트레이드오프).

- `completeStep`(범용 완료/취소) 자체는 CERT를 막지 않았다 — 프로필에서 직접 자격증을 추가했을 때 일치하는 CERT 단계를 자동 완료하는 기존 기능(`syncCertAddedFromProfile`, 09-23 합의)이 내부적으로 이 메서드를 그대로 쓰고 있어서, 서비스 레벨에서 막으면 그 기능이 깨지기 때문. 화면(`roadmap.jsp`)에서 CERT용 완료 체크 버튼만 없애 증빙 제출 쪽으로 유도.

## 8. [TEST] 바이패스 버튼 — 제거 → 재추가 반복

- 파일 업로드가 전부 필수가 되면서 테스트할 때마다 막혀서 "[TEST] 파일 없이 통과" 버튼을 PROJECT/ENTRY·EXPERT/CORE·ADVANCED/CERT 네 곳에 넣었다.
- 실기능(PDF 업로드 플로우) 검증이 끝났다고 판단해 한 번 지웠는데, 사용자가 "테스트할 때 파일 매번 넣는 게 힘들어서 만들어달라 한 거였다"고 정정 — 네 곳 모두 다시 추가했다. **실제 운영 배포 전에는 반드시 제거해야 한다.**
