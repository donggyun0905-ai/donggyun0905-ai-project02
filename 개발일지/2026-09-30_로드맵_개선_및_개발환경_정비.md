# 로드맵 개선(다음 단계 미리보기 · LLM 아이디어 제안) + 집 PC 개발환경 정비

날짜: 2026-09-30
관련 커밋: `477b217`, `955eaa6`

## 1. 개요

학교-집-학교를 오가며 작업하는 루틴이라, 오늘은 크게 두 갈래다. 하나는 집 PC에서 IntelliJ·Tomcat 개발 환경을 처음부터 다시 잡은 과정, 다른 하나는 로드맵 기능을 실제로 써보면서 발견한 버그 수정과 개선(다음 단계 미리보기, LLM 프로젝트 아이디어 제안)이다.

## 2. 집 PC 개발 환경 재정비

- **IntelliJ에 Application Servers 메뉴가 안 보임** — Community 버전인 줄 알았는데 실제 원인은 파워 세이브 모드(Power Save Mode)가 켜져 있던 것. 해제 후 정상적으로 나타남.
- **Tomcat 미설치** — 이 컴퓨터엔 Tomcat을 받은 적이 없었다. `C:\Tomcat\apache-tomcat-10.1.60`에 새로 설치.
- **Maven import가 반쪽만 됨** — `.idea/misc.xml`엔 `pom.xml`이 등록돼 있는데 실제 모듈(`.iml`)로는 연결이 안 된 상태였다. Maven 툴윈도우에서 "Reload All Maven Projects"로 해결.
- **`.env`가 엉뚱한 DB를 가리키고 있었음** — `DB_URL`이 `dmart`(재고관리용, 전혀 다른 프로젝트)로 설정돼 있었다. 같은 서버(`cdn.ditanet.duckdns.org:8306`)에 진짜 프로젝트 DB인 `spec_odyssey`가 따로 있어서 그쪽으로 수정. 이 DB 서버는 로컬이 아니라 원격 서버이고, 팀이 이미 실사용 중인 DB(회원 2명, 격차분석 4건, 로드맵 3건 기존 존재)라는 것도 이 과정에서 확인했다.

## 3. `CertificationDao` COMMON 카테고리 버그 수정 (`477b217`)

- **문제**: `findByJobCategory`가 `job_category = ?`로만 조회해서, 특정 직무에 안 묶이는 범용 자격증(`COMMON`, 컴활·정보처리기능사 등)이 어떤 직무를 골라도 로드맵 자격증 후보에 전혀 안 떴다.
- **원인**: `db-design.md`와 `role-plan.md`(특이사항 ⑦)에 이미 "`job_category IN (:target, 'COMMON')`로 조회해야 한다"고 명시돼 있었는데 코드에 반영이 안 돼 있었다.
- **수정**: 조건에 `OR job_category = 'COMMON'` 추가, 대상 직무 카테고리를 COMMON보다 먼저 보여주도록 정렬(`ORDER BY (job_category = ?) DESC, ...`) 추가.
- **검증**: 격리된 MySQL에 전체 SQL 체인 적용 후 실제 조회로 확인 — BACKEND 직무 조회 시 정보처리기사 등 BACKEND 자격증 다음에 컴활(COMMON)이 순서대로 나옴. `mvn test` 전체(96개) 회귀 없음 확인.

## 4. 로드맵 "다음 단계 미리보기" 추가 (`955eaa6`)

- **문제의식**: 로드맵은 부족 기술을 점수 내림차순으로 정렬해 티어(`ENTRY→CORE→ADVANCED→EXPERT`)당 5개씩 나눠 담는데, 화면엔 지금 열린 티어(보통 ENTRY 7개: CERT 1 + PROJECT 1 + SKILL 5)만 보이고 나머지는 완전히 숨겨져 있었다. 실제 공유 DB 데이터로 확인해보니 부족 기술 13개짜리 로드맵이 ENTRY 7개만 보이고 CORE 5개·ADVANCED 3개는 안 보이는 상태였다.
- **판단**: 완전히 숨기는 건 `db-design.md`가 원래 권고한 "현재 tier + 다음 tier까지만 노출하고 나머지는 흐리게 표시"보다 더 엄격한 것이었고, "로드맵(여정 전체를 보여준다)"이라는 제품 정체성과도 안 맞는다고 판단해 다음 티어 미리보기를 추가하기로 했다.
- **구현**: `RoadmapService`에 이미 있던 `getNextLockedTier()`(안 쓰이고 있었음)를 그대로 활용해, `roadmap.jsp`에 잠긴 다음 티어를 `opacity:0.65`로 흐리게 보여주는 카드 섹션을 추가했다. 액션 버튼은 없음 — 잠긴 단계는 완료할 수 없다.

## 5. LLM 기반 프로젝트 아이디어 제안 — `ProjectIdeaService` 신규 (`955eaa6`)

- **배경**: PROJECT 단계는 부족 기술이 몇 개든 항상 1개뿐인데, 안내 문구가 "부족한 기술: X, Y, Z, 이걸로 뭔가 만들어보세요" 정도로 뭉뚱그려져 있었다. `RoadmapService` 클래스 주석에도 애초에 "구체 프로젝트 추천은 LLM 붙을 때 고도화"라고 적혀 있던 부분이다.
- **설계**: `TrendLlmService`가 이미 잡아둔 Groq 호출 패턴(재시도, JSON 강제 응답, 파싱 실패 처리)을 그대로 재사용해 `ProjectIdeaService`를 새로 만들었다. 목표 직무 + 부족 기술 목록을 주면 신입 개발자가 2~4주 안에 완성할 수 있는 구체적인 프로젝트 아이디어(제목+설명) 1개를 JSON으로 받는다.
- **트랜잭션 경계**: LLM 호출은 `RoadmapService.generate()`가 DB 트랜잭션을 열기 전에 미리 끝낸다 — 느리거나 실패해도 DB 커넥션을 물고 있으면 안 된다(claude.md "외부 API 호출은 타임아웃을 직접 지정한다"). 실패하면 예외를 잡아 기존 고정 문구로 조용히 대체한다(FR-111 취지) — 아이디어 생성 실패가 로드맵 생성 자체를 막지 않는다.
- **검증**: 실제 배포 환경(Tomcat + 공유 DB)에서 회원가입→로그인→희망직무 설정(백엔드 개발자)→격차분석→로드맵 생성까지 curl로 실행. Groq가 실제로 아래 아이디어를 생성했다 (폴백 문구 아님):

  > 💡 도서관 대출 관리 API — Spring Boot와 MySQL을 이용해 도서관 대출·반납·예약 기능을 제공하는 RESTful API를 구현합니다. 도서, 회원, 대출 이력 CRUD와 대출 가능 여부 검사, 연체료 계산 로직을 포함하고, Dockerfile과 docker-compose로 애플리케이션·DB를 컨테이너화해 손쉽게 배포·테스트할 수 있도록 합니다.

  테스트에 쓴 계정은 확인 직후 공유 DB에서 바로 삭제해 원상태로 되돌렸다.

## 6. 테스트용 PROJECT 단계 패스 버튼 (`955eaa6`)

기능 검증 중 PROJECT 단계가 파일 첨부까지 필수라 테스트할 때마다 막혀서, `roadmap.jsp`에 "[TEST] 파일 없이 통과" 버튼을 추가했다. 이미 있던 범용 완료 액션(`action=complete`)을 그대로 재사용해서 새 백엔드 코드는 없다 — 점수는 정상 적립되지만 프로필에 프로젝트/파일은 안 채워진다. **실기능 검증이 끝나면 이 버튼은 지워야 한다.**

## 7. 다음에 할 일

우선순위 순서는 아니고, 팀과 상의해서 정할 것들:

1. **기술 부족 SKILL 단계에 "완료 체크"만 있는 게 아니라, 실제로 연습해볼 수 있는 외부 링크(프로그래머스 등) 연결** — 지금은 스스로 공부하고 와서 체크만 하는 구조라 검증 수단이 없음.
2. **로드맵 단계 순서(점수 배점) 로직 재검토** — 지금은 `REQUIRED=+2, PREFERRED=+1, 정보없음=0`으로만 정렬하는데, 이게 실제로 균형 잡힌 순서를 만드는지 다시 봐야 함.
3. **기술 스택 매칭에 시맨틱(임베딩) 기법 적용** — 지금은 `ExactMatcher`(정확 일치)만 있어서 "Node.js"와 "NodeJS"를 다른 기술로 취급함. TD-1 원래 설계(DJL+ONNX, ko-sroberta-multitask)대로 가거나 임베딩 API로 전환.
