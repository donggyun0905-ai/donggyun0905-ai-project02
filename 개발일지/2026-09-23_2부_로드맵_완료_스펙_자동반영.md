# 2부 — 화면 표시 + 로드맵 완료 시 스펙 자동 반영

날짜: 2026-09-23
관련 커밋: `9c72a95`

## 1. 개요

1부에서 만든 등급 체계를 화면에 보여주고(팀 합의 사항 "화면표시는 이대로"), 이어서 "로드맵 완료 체크를 누르면 그 결과가 실제 스펙/기술스택에도 반영되냐"는 질문을 받아서 SKILL·CERT·PROJECT 세 가지 단계 타입 각각에 대해 완료 시 프로필 자동 반영 로직을 만들었다.

## 2. 헤더·프로필 등급 표시

`SessionFilter`가 로그인된 모든 요청에 `totalScore`/`currentTier`/`tierLogoPath`를 request attribute로 얹어주도록 확장했다 — 헤더가 모든 페이지에 `<jsp:include>`되므로 필터 한 곳만 고치면 전체에 반영된다. 적립 이력이 없는 신규 사용자도 0점 기준으로 비기너 등급이 뜨게 `ScoreService.getTierForScore(int)`를 조회 전용으로 분리했다. 로고 파일명은 `LEVEL_TIER`에 컬럼을 안 두고 `min_score` 오름차순 순서와 1:1로 맞췄다(5단계 순서는 안 바뀐다는 전제).

### 2-1. 트러블슈팅 — 이미지가 잘리고 찌그러짐

사용자가 이미지를 다시 넣었는데도 잘린 채로 보인다는 신고가 있었다. 배포된 `target/spec-odyssey`와 소스를 직접 비교해서 빌드/배포 자체는 정상 반영됐다는 걸 확인했고, 원인은 **브라우저 캐시**였다(강력 새로고침으로 해결).

이후 이미지 자체를 다시 확인하는 과정에서 진짜 버그 하나를 잡았다 — 5장 로고의 실제 픽셀 비율이 제각각(335×406 ~ 407×406, 가로세로비 0.82~1.0)인데, `<img>`에 `width`·`height`를 같이 고정해놨던 게 티어별로 다르게 눌리거나 늘어날 뻔했다. `height`만 지정하고 `width`는 빼서 브라우저가 원본 비율대로 그리게 고쳤다.

## 3. SKILL 단계 완료 → USER_SKILLS 자동 반영 + 숙련도 승급

- 완료 시 `USER_SKILLS`에 없으면 새로 등록(`BEGINNER`), 있으면 유지.
- 같은 스킬을 겨냥한 SKILL 단계 완료 횟수를 세서(`RoadmapStepDao.countCompletedByUserAndSkill`) 10회 이상이면 `INTERMEDIATE`, 30회 이상이면 `ADVANCED`로 자동 승급. 완료 취소로 나중에 횟수가 줄어도 이미 오른 숙련도는 내리지 않는다(단조 증가만 허용).

## 4. CERT 단계 완료 → USER_SPECS 자동 반영

`CERTIFICATION` 마스터에서 이름·발급기관을 그대로 복사해 등록한다. `USER_SPECS`엔 별도 UNIQUE 제약이 없어서, 같은 자격증이 이미 있으면 앱 레벨에서 중복 등록을 막는 가드(`existsActiveByUserAndTitle`)를 넣었다.

## 5. PROJECT 단계 완료 — 파일 업로드 플로우 (범위 확장)

PROJECT는 SKILL/CERT와 달리 자동으로 채울 값이 없다(구체적으로 뭘 했는지는 사용자만 안다). 사용자가 "완료하기 버튼만 있는 게 아니라 파일을 올릴 수 있게 하고, 스펙/기술스택 입력을 필수로 받은 다음 완료하기를 누를 수 있게 하자"고 요청해서 별도 플로우를 새로 만들었다.

- 서류 보관함(`DOCUMENTS`, FR-61~63)이 이미 스키마·DAO까지 다 있어서(2주차 이전 공용 뼈대 작업 때 만들어둔 것) 스키마 변경 없이 그대로 재사용했다 — `db-design.md`에 "산출물이 USER_PROJECTS에 붙는다"는 설계 판단이 이미 적혀 있었다.
- 파일 저장 방식은 세 가지를 확인 후 결정: ① 첨부 필수 여부 → 필수, ② 저장 위치 → webapp 밖 디스크 + 서블릿으로만 다운로드(URL 직접 노출 방지), ③ 파일 개수 → 여러 개 허용.
- `FileStorageUtil` 신설: `.env`의 `UPLOAD_DIR`(없으면 `<사용자 홈>/spec-odyssey-uploads`)에 UUID 파일명으로 저장, SHA-256 체크섬 계산, 실행파일류 확장자 차단.
- `RoadmapServlet`에 `@MultipartConfig`(파일당 20MB, 요청 전체 100MB) 추가. `generate`/`complete` 액션은 그대로 `x-www-form-urlencoded`라 영향 없음.
- `DocumentDownloadServlet`(`/documents/*`) 신설 — 파일은 webapp 밖에 있어 URL로 직접 못 받고, 이 서블릿이 세션의 본인 소유 문서인지 확인한 뒤에만 스트리밍한다.
- `RoadmapService.completeProjectStep(userId, stepId, projectInput, uploadedFiles)`: `USER_PROJECTS` 생성 + `DOCUMENTS` 여러 건 등록 + 단계 완료 + 점수 적립을 한 트랜잭션으로.
- 프로필 페이지 "프로젝트·경험" 목록에 첨부파일 다운로드 링크(📎)도 같이 추가했다(FR-62).
