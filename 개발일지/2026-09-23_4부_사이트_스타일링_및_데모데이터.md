# 4부 — 사이트 스타일링 + 데모 데이터 시딩 + 역할 논의

날짜: 2026-09-23
관련 커밋: 스타일링·데모데이터는 3부 커밋(`9c72a95`) 이후 작업이라 아직 미커밋 상태

## 1. 개요

기능 쪽 작업을 커밋한 뒤, "이제 좀 꾸며볼래?"라는 요청으로 사이트 전체에 스타일을 입혔다. 이어서 "지금 할 일 5개를 다 완료 처리했는데 다음 티어로 안 넘어간다"는 신고를 받아 원인을 진단하고 데모 계정에 실제 서비스 로직을 태워서 더 풍부한 데이터를 채워 넣었다. 마지막으로 남은 요구사항 영역(일일미션·트렌드 사이드바) 담당 여부를 확인했다.

## 2. 사이트 전체 스타일링

시작 전에 두 가지를 확인했다 — ① 적용 범위(프로필·로드맵만 vs 사이트 전체), ② 분위기(깔끔한 미니멀 vs 항해 테마). 둘 다 사이트 전체 / 항해 테마로 결정됐다 — 등급 로고(나침반)가 이미 "항해" 테마로 맞춰져 있어서 자연스러운 선택이었다.

- `css/style.css` 신설 — 프레임워크 없이 순수 CSS(CLAUDE.md 규칙). 나침반 로고 톤(나무→청동→은→금→틸골드)을 CSS 변수로 뽑아서 전체 색상 체계를 맞췄다.
- `body`를 CSS Grid로 잡아서 헤더(전체 폭) / 본문 + 사이드바(2열) / 푸터 레이아웃을 구성했다. FR-54 트렌드 사이드바 자리(`#trend-sidebar`)는 아직 비어있는데, `:empty { display: none; }`로 비어있는 동안은 자동으로 숨겨지고 나중에 내용이 채워지면 저절로 나타나게 해뒀다.
- 8개 화면(index, login, signup, profile, roadmap, error + header/footer) 전부에 카드형 레이아웃 적용. 폼은 카드로, 스펙·프로젝트·스킬·로드맵 단계 목록은 카드형 리스트로, 완료된 항목은 틸 색 테두리로 구분.
- 로드맵 단계에 ENTRY/CORE·단계 타입을 칩(chip)으로 표시, 진행도는 숫자뿐 아니라 실제 바(bar)로도 시각화.
- `mvn test` 67개 그대로 통과 확인(스타일링은 JSP/CSS만 건드려서 Java 테스트엔 영향 없음) 후 `mvn package`로 재배포.

## 3. "다음 티어로 안 넘어간다" — 원인 진단

`demo_roadmap`(user 358) 계정으로 확인해보니 부족 기술이 3개(Spring Boot·Docker·MySQL)뿐이라 5개가 전부 ENTRY 안에 들어가고, CORE로 넘어갈 게 아예 없었다. 점수도 정확히 500점이라 `취준생` 등급 경계선에 막 걸쳐 있던 상태였다. DB를 직접 들여다보고 `current_tier_id=19`(취준생)로 이미 정상 계산돼 있다는 것도 확인했다 — "안 넘어간다"는 체감은 CORE에 넘어갈 다음 항목 자체가 없어서였다는 게 결론.

## 4. 데모 데이터 시딩 — 실제 서비스 로직을 그대로 태워서

사용자가 "예시데이터로 다 넣어달라"고 요청했는데, 그냥 SQL로 점수·등급 값을 직접 INSERT하면 실제 로직(점수 계산·등급 판정·숙련도 승급 등)과 어긋날 위험이 있어서, 한 번 쓰고 지울 임시 러너(`SeedDemoDataRunner`, `src/test/java`에 뒀다가 실행 후 바로 삭제)를 만들어 `RoadmapService`/`ScoreService`를 코드로 직접 호출하는 방식으로 채웠다.

- 백엔드 직무에 새 요구 기술 10개(NGINX, Redis, Kubernetes, GraphQL, RabbitMQ, Elasticsearch, gRPC, Terraform, JPA, JUnit) 추가, 6개 REQUIRED·4개 PREFERRED로 등록.
- 새 격차분석 생성(기존에 배운 4개는 MET, 새 10개는 MISSING) → `roadmapService.generate()`로 로드맵 v2 생성 → CERT 1 + PROJECT 1 + SKILL ENTRY 5 + SKILL CORE 5, 총 12단계 전부 `completeStep`/`completeProjectStep`으로 완료 처리.
- 결과: 누적 점수 500 → **1700점**, 등급 취준생(견습 항해사) → **실전러(정식 항해사)** 승급 확인. 이미 가진 자격증(정보처리기능사) 대신 다음 난이도 자격증(정보처리산업기사)이 자동으로 추천·등록되는 것도 확인 — 자격증 로테이션 로직이 실제로 동작함을 재확인.
- 실행 후 러너 파일은 삭제(정식 코드가 아니므로), `mvn test` 67개 그대로 통과 재확인.

## 5. 남은 요구사항 영역 확인 — 일일미션 · 트렌드 사이드바

FR-51~55(일일미션 + 기술 트렌드 사이드바)가 5명 중 아무에게도 배정 안 된 상태라는 걸 다시 확인했다. `PROBLEM`/`USER_DAILY_MISSION`/`TREND_TECH` 테이블은 DAO/DTO까지만 있고(2주차 이전 공용 뼈대 작업 때 만든 것) Service/Controller는 없음, 데이터도 0건 — 격차분석 때와 같은 출발선.

두 영역의 성격이 다르다는 점을 짚었다 — FR-51~53(일일미션·문제난이도)은 이미 만든 `LEVEL_TIER.problem_level_min/max`와 바로 연결되는 반면, FR-54~55(트렌드 사이드바)는 워크넷·뉴스 등 외부 데이터 수집 쪽이라 직무발굴(youngjun) 작업에 더 가깝다. 결론은 보류 — 다음에 이어서 논의하기로 했다.
